SCIM provisions and deprovisions people from your identity provider into Site Qwality. Roles travel with them. The mapping is exact-string, case-sensitive, and fail-soft: an unknown name becomes Member rather than rejecting the user.

Requires an Enterprise plan. See [plan limits](/getting-started/plan-limits/).

## Set up the connection

<Steps>

1. As a Super Admin, open **Settings → SCIM provisioning** in Site Qwality and create a connection. Copy the **SCIM base URL** and the **bearer token** (shown once).

2. In your identity provider (Okta, Entra ID, OneLogin, JumpCloud, and so on) create a SCIM 2.0 application. Paste the base URL and token.

3. Map groups or roles in the IdP to the Site Qwality role IDs in the table below. The IdP must send the `role_id`, not a display label.

4. Push one test user, then check **Settings → Users**. They should appear with the mapped role. If the role looks wrong, the IdP is sending a string that is not in the table.

</Steps>

## Role IDs the IdP must send

Send one of these strings as the member's role. They are the same IDs you pick in the invite dialog.

| IdP / Stytch `role_id` | Dashboard role | What they can do |
|---|---|---|
| `super_admin` | Super Admin | Everything, including billing, roles, SSO, and SCIM. |
| `admin` | Admin | Team, API keys, and the audit log. Not billing, roles, SSO, or SCIM. |
| `billing_admin` | Billing Admin | Billing only. Not team or role management. |
| `member` | Member | Full product access. No team, credentials, or billing. New users start here. |
| `viewer` | Viewer | Read-only. Can still acknowledge and resolve incidents if they are on call. |
| `auditor` | Auditor | Read-only, plus the [audit log](/enterprise/audit-log/). |

`owner` is a retired alias for Super Admin. Existing grants still work; do not assign it to new people.

If a member has more than one of these roles, Site Qwality keeps the **first** one in that list that appears on the member. Extra roles are ignored.

## Unknown names become Member

These do **not** map and fall through to Member:

- Stytch's implicit `stytch_member` (every member has it; it is not a Site Qwality role)
- Custom Stytch roles you created in the Stytch dashboard
- Display names (`Super Admin`, `Admin`, `Viewer`)
- Okta/Entra group names (`Engineering`, `On-Call`)
- Empty role lists
- Near misses such as `SuperAdmin`, `super-admin` and `admins`

The user is still created, as Member. A Super Admin can raise the role in **Settings → Users**, or you can fix the IdP mapping and push the user again.

## Who cannot be removed

Two people are protected, so the IdP cannot take the account down by deleting them.

| Who | Dashboard | SCIM deprovision |
|---|---|---|
| The account's original user (the primary user) | Cannot be deleted or demoted | The delete is ignored. They stay a Super Admin. |
| The last Super Admin | Cannot be deleted or demoted | Do not remove their Super Admin group in the IdP until someone else holds `super_admin`. |

Everyone else is removed when the directory deletes them, even if they are on call. They are taken out of every rotation and escalation level in the same step, the people after them in a rotation move up a place, the removal is recorded in the [audit log](/enterprise/audit-log/), and if they were in any, every Super Admin gets an email listing them. Check that each of those still pages someone.

Always keep at least two Super Admins if you manage roles from the directory. Map a break-glass group to `super_admin` so a directory outage does not lock you out of billing and SCIM.

## Invites still work

SCIM does not replace [invites](/getting-started/account-and-team/): you can still invite people from **Settings → Users**. If SCIM later pushes the same email, Site Qwality attaches the directory member to the existing user rather than creating a duplicate.
