Choose **New dashboard** > **From a template**, pick a template and choose **Create dashboard**. You get an ordinary dashboard that you can edit, clone, share and delete like any other. Changing it never changes the template.

Each template shows whether your account has its data, such as **Uses your monitors** or **Needs monitors**:

- The uptime boards and Executive summary need monitors.
- Incidents and reliability needs at least one incident, at any time.
- Web vitals needs a RUM application with sessions in the last 7 days.
- Logs overview needs logs in the last 7 days.
- Service health needs spans in the last 7 days.

You can create a dashboard from a template that has no data yet. Its widgets show **No data** until the data arrives.

To learn the widgets, open a template widget's editor and see how its queries, filters and formulas are set up.

## The seven templates

### Uptime overview

For: the daily "is everything up?" board.

- Monitor status
- Monitor grid, all monitors, grouped by type
- Uptime percent, with comparison to the previous period
- Average response time by region, with incident overlay
- Failed checks, as bars
- Slowest monitors by p95, as a top list
- Uptime bars, 30 days
- Expiring certificates and domains
- Open incidents

### Monitor deep dive

Variable: `$monitor`. For: one monitor, in detail.

- Uptime and p95 response time, as query values
- Response time p50, p95 and p99
- Phase breakdown as a stacked area: DNS, connect, TLS, TTFB and download
- Response time by region
- Checks against failures
- Uptime bars, 90 days
- Downtime overlay

### Incidents and reliability

For: how often things break and how fast you recover.

- Open incidents, as a value
- Incidents by severity, as stacked bars
- MTTR and MTTA, as values with comparison
- Incident list
- Downtime by monitor, as a top list
- Uptime bars

### Web vitals

Variable: `$app`. For: front-end performance of one RUM application.

- Sessions, views and error session rate, as values with comparison
- Web Vitals rail
- LCP and INP p75 over time
- Top pages by views
- Slowest pages by LCP p75
- Sessions by browser, as a pie
- Sessions by country, as a top list

### Logs overview

Variable: `$env`. For: what your logs say right now.

- Log volume by level, as stacked bars
- Error logs, as a value
- Top sources
- Top hosts
- Error log stream

### Service health

Variable: `$service`. For: one service's traffic, errors and latency.

- Requests, error rate and p95 latency, as values with comparison
- Requests and errors over time
- Latency p50, p95 and p99
- Slowest operations, as a top list
- Recent error traces

### Executive summary

For: a one-screen status report.

- Uptime over 30 days, incidents, MTTR, sessions, LCP p75 and error rate, as values with comparison
- Uptime bars
- Incidents over time

## Template variables

Variables in templates default to **All**. The exceptions are `$monitor` and `$app`, which default to your first monitor or first RUM application when the dashboard is created. See [variables](/dashboards/queries/#variables).
