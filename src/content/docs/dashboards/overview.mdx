A **dashboard** is a named collection of widgets pinned to a layout, with a shared global time range. Build them for war-rooms during incidents, for the wall TV at standup, or for the CTO's daily dashboard refresh.

## When to use dashboards

- One canonical "is everything OK?" view per service.
- Incident war-rooms, with every relevant signal pinned in one place.
- Executive summaries built from top-line business KPIs in your metric pipeline.

## When NOT to use them

- For ad-hoc exploration. Use the per-pillar Explorers (Logs, Metrics, Traces) instead.
- For alerting. Alerts live in the [incident management](/incident-management/overview/) layer, not on a chart.

## Anatomy

| Field | Description |
|---|---|
| `name` | Required, displayed at the top. |
| `description` | Optional context. |
| `global_time_range` | Object: `{type: "relative", value: "1h"}` or `{type: "absolute", from: ..., to: ...}`. Every widget uses it. |
| `auto_refresh_seconds` | Optional polling interval. Common values: `30`, `60`, `300`. |
| `widgets[]` | Array of `DashboardWidget`s. |

## Widget types

| Type | Renders |
|---|---|
| `timeseries` | Line chart over time: a metric's average, or an HTTP monitor's response time and success rate. |
| `stat` | Single big number: the latest average of a metric, or an HTTP monitor's latest response time. |
| `table` | Rows of recent log lines, recent traces, or a metric's points. |
| `log_stream` | The newest log lines in the time range, across your whole account. Refreshes with the dashboard. |
| `monitor_status` | One HTTP monitor's status (operational, degraded or down) and uptime. |
| `text` | Plain text for notes and headers. |

## Data sources

| Source | Use |
|---|---|
| `metrics` | One metric, by name. |
| `logs` | The newest log lines in the time range. |
| `traces` | The most recent traces in the time range. |
| `uptime` | One HTTP monitor's response time and success rate. |
| `none` | For `text` widgets that don't query anything. |

Widgets do not take filters, aggregations or a group-by: a metric widget always shows the average across every series of that metric, and log and trace widgets show the whole account. Use the Logs, Metrics and Traces pages when you need to narrow things down. There is no RUM widget.

## Widget layout

Each widget has a `layout: {x, y, w, h}` on a 12-column grid. Default is `{x: 0, y: 0, w: 6, h: 4}`, which is half-width and 4 rows tall. Drag to reorder in the dashboard editor.

## Time range

1. The dashboard has one time range, its `global_time_range`.
2. Anyone can change it at the top of the page; the new range is saved to the dashboard for everyone.
3. Every widget uses that range. The API accepts a `time_range_override` on a widget, but the dashboard does not apply it.

## Auto-refresh

Set `auto_refresh_seconds` to poll every N seconds. Useful for war-room dashboards on a wall TV. Don't set it on dashboards that drive expensive aggregations. Refreshing every 30 seconds across 20 metric widgets is real load on ClickHouse.

<Aside type="tip">
Dashboards are per-account, not per-user. There's no privacy boundary, so every team member sees every dashboard. Use `description` and naming conventions to make it clear when a dashboard is owned by a specific team.
</Aside>
