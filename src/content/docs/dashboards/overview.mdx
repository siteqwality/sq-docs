A **dashboard** answers one question for one team, service or customer: is everything OK, and if not, where?

Uptime, incidents, RUM and backend telemetry live in the same account, so one board can hold a monitor grid, p95 latency by region with incident overlays, LCP p75 and a stream of error logs.

Requires a paid plan. See [plan limits](/getting-started/plan-limits/).

## What a dashboard is

A dashboard is a 12-column grid of **widgets**, plus a default time range, a refresh setting and a set of **variables**. All of it is stored as one JSON document that you can [export and import](/dashboards/reference/#json-export-format).

Dashboards belong to the account, not to a person, and every member can view every one. Use names, tags and the description to show who owns a board.

## Finding dashboards

The dashboards list searches by name and tags. Star a board to add it to your favorites, or pick **Mine** to show only the dashboards you created. Sort by recently viewed, last updated or name. A deleted dashboard waits in **Recently deleted** for 30 days, and you can restore it from there.

## Data sources

Each query reads from one of six sources.

| Source | Reads | Example measures |
|---|---|---|
| `monitors` | HTTP and browser checks, and downtime including cron | Uptime, response time, check phases, failed checks, downtime |
| `incidents` | Incidents | Incidents opened, open incidents, MTTR, MTTA |
| `rum` | Real user monitoring | Sessions, page views, errors, Web Vitals, rage clicks |
| `logs` | Log events | Log count by level, source, host or environment |
| `metrics` | Any metric you send | The metric's value, by tag |
| `traces` | Distributed traces | Requests, errors, error rate, latency |

Every source lists its measures, fields and aggregations on the [data sources](/dashboards/data-sources/) page.

## Widgets

There are fifteen widget types in four groups.

| Group | Widgets |
|---|---|
| Charts | Time series, Query value, Top list, Table, Pie |
| Monitoring | Monitor grid, Monitor status, Uptime bars, Incidents, Certificate and domain expiry |
| Logs, traces and RUM | Log stream, Trace list, Web Vitals |
| Text and layout | Note, Section |

The five chart widgets are built from lettered queries and formulas such as `a / b * 100`. The rest are built for one job each and take filters. See [widgets](/dashboards/widgets/) and [queries, formulas and variables](/dashboards/queries/).

## Templates

Seven built-in [templates](/dashboards/templates/) give you a working board. Creating one makes an ordinary dashboard that you can edit freely.

## Variables

A variable such as `$region` or `$service` is a dropdown in the variables bar. It is bound to a field of a source, and widgets use it in their filters. Pick `us-east-1` and every widget that filters on `$region` follows. The selection is stored in the URL, so a link carries it. See [variables](/dashboards/queries/#variables).

## Time controls

The time picker takes presets, a calendar or typed text such as `yesterday` or `since Oct 1`. A range can be live or paused, you can step, zoom and pick a timezone, and a single widget can override the dashboard range.

Changing the range is a view, not an edit. Your change lives in the URL and never overwrites the dashboard's saved default. To change the default, enter edit mode and choose **Save as default time**.

Dashboards also refresh themselves: the `auto` setting picks a cadence from the range. Full syntax and the refresh table are in the [reference](/dashboards/reference/#time-range-syntax).

## Editing and history

Dashboards open read-only. Choose **Edit** (or press `e`) to change one, then **Save** or **Discard**.

In edit mode you can arrange widgets, group them under sections, copy and paste them between dashboards, and undo and redo. If someone else saved first, a conflict dialog tells you instead of overwriting their work.

Every save is a version with a summary of what changed. **Version history** lists them, previews any one, and restores it as a new version.

A dashboard can be locked. Only its creator and account admins can edit a locked dashboard. Viewers and Auditors can only view. See [roles and permissions](/dashboards/reference/#roles-and-permissions).

## Sharing

**Share** creates a public, read-only link with its own allowed time ranges, variables, theme and expiry. **TV mode** (`?tv=1`) removes the page chrome and enlarges the type for a wall screen. See [sharing](/dashboards/sharing/).

## Dashboards or explorers

Use a dashboard for the board you check every day, and an explorer for open-ended digging. A widget's **Open in explorer** action carries its filters and time range across.

Dashboards do not send alerts. Threshold alerts are set up in the [observability](/observability/overview/) pillars, and incident notifications come from [incident management](/incident-management/overview/).
