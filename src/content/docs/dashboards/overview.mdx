A **dashboard** answers one question for one team, service or customer: is everything OK, and if not, where?

Uptime, incidents, RUM and backend telemetry live in the same account, so one board can hold a monitor grid, p95 latency by region with incident overlays, LCP p75 and a stream of error logs. There is no integration step between them.

<Aside type="note" title="Dashboards are paid-plan only">
Creating, editing and querying dashboards needs the `custom_dashboards` feature, which every paid plan includes. See [plan availability](#plan-availability).
</Aside>

## What a dashboard is

A dashboard is a 12-column grid of **widgets**, plus a default time range, a refresh setting and a set of **variables**. All of it is stored as one JSON document that you can [export and import](/dashboards/reference/#json-export-format).

Every member of the account can view every dashboard. Dashboards are per account, not per person. Use names, tags and the description to show who owns a board.

The actions menu holds Edit, Clone, Export JSON, Version history, Share, TV mode, Copy link, Settings and Delete.

## Finding dashboards

The dashboards list searches by name and tags. Star a board to add it to your favorites, or pick **Mine** to show only the dashboards you created. Sort by recently viewed, last updated or name. A deleted dashboard waits in **Recently deleted** for 30 days, and you can restore it from there.

## Data sources

Each query reads from one of six sources.

| Source | Reads | Example measures |
|---|---|---|
| `monitors` | HTTP and browser checks, and downtime including cron | Uptime, response time, check phases, failed checks, downtime |
| `incidents` | Incidents | Incidents opened, open incidents, MTTR, MTTA |
| `rum` | Real user monitoring | Sessions, page views, errors, Web Vitals, rage clicks |
| `logs` | Log events | Log count by level, source, host or environment |
| `metrics` | Any metric you send | The metric's value, by tag |
| `traces` | Distributed traces | Requests, errors, error rate, latency |

Every source lists its measures, fields and aggregations on the [data sources](/dashboards/data-sources/) page.

## Widgets

There are fifteen widget types in four groups. The add-widget tray lets you search them and click or drag one onto the grid.

| Group | Widgets |
|---|---|
| Charts | Time series, Query value, Top list, Table, Pie |
| Monitoring | Monitor grid, Monitor status, Uptime bars, Incidents, Certificate and domain expiry |
| Logs, traces and RUM | Log stream, Trace list, Web Vitals |
| Text and layout | Note, Section |

The five chart widgets take up to ten lettered queries and up to five formulas such as `a / b * 100`. The rest are built for one job each and take filters. See [widgets](/dashboards/widgets/) and [queries, formulas and variables](/dashboards/queries/).

## Templates

Seven built-in dashboards give you a working board in one click:

- Uptime overview
- Monitor deep dive
- Incidents and reliability
- Web vitals
- Logs overview
- Service health
- Executive summary

The gallery marks each one **Has data** or **No data yet** for your account. Creating one makes an ordinary dashboard that you can edit freely. See [templates](/dashboards/templates/).

## Variables

A variable such as `$region` or `$service` is a dropdown in the variables bar. It is bound to a field of a source, and widgets use it in their filters. Pick `us-east-1` and every widget that filters on `$region` follows.

Variables can be single or multi select, can include **All**, and take their values from your data. They are stored in the URL, so a link carries the selection. Hover a variable to highlight the widgets that use it.

## Time controls

The time picker offers presets (15m, 1h, 4h, 1d, 2d, 7d, 30d, 90d) and a calendar. You can also type a range: `3h`, `90m`, `yesterday`, `this week`, `since Oct 1` or `Oct 1 - Oct 3`.

- **Live or paused.** A live range slides forward with the clock. A paused range stays put.
- **Step and zoom.** Step back or forward one window, zoom out, or drag across any time chart to zoom in. **Back** returns to the previous range.
- **Timezone.** Show times in your browser's zone, in UTC, or in the dashboard's own zone.
- **Per-widget range.** A widget can override the dashboard range. It then shows a time badge.

Changing the range is a view, not an edit. Your change lives in the URL and never overwrites the dashboard's saved default. To change the default, enter edit mode and choose **Save as default**.

Dashboards also refresh themselves. The `auto` setting picks a cadence from the range, from every 10 seconds at 15m up to hourly above 7d. Refresh pauses while the tab is hidden, and only widgets on screen query. Full syntax and the refresh table are in the [reference](/dashboards/reference/#time-range-syntax).

## Editing and history

Dashboards open read-only. Choose **Edit** (or press `e`) to change one, then **Save** or **Discard**.

In edit mode you can drag, resize, duplicate and delete widgets, group them under sections, copy and paste them between dashboards, and undo and redo. The widget editor opens in a drawer with a live preview. If someone else saved first, a conflict dialog tells you instead of overwriting their work.

Every save is a version with a summary of what changed. **Version history** lists them, previews any one, and restores it as a new version.

A dashboard can be locked. Only its creator and account admins can edit a locked dashboard.

## Sharing

**Share** creates a public, read-only link. You choose the allowed time ranges, which variables viewers may change, the theme and an expiry. You can pause or revoke the link at any time. **TV mode** (`?tv=1`) removes the page chrome and enlarges the type for a wall screen. See [sharing](/dashboards/sharing/).

## Who can do what

| Role | Access |
|---|---|
| Viewer, Auditor | View only. Every action that changes a dashboard is refused. |
| Member, Billing Admin | View, create, edit and share. A locked dashboard is editable only by its creator. |
| Admin, Super Admin | Everything a Member can do, and edit locked dashboards. |

## Plan availability

Dashboards are on every paid plan. The feature key is `custom_dashboards`. On the free plan, creating, editing, importing, cloning and querying return `403`.

If an account moves from a paid plan to free, its dashboards stay. You can still list, open, export and delete them, behind an upgrade notice.

## Dashboards or explorers

Use a dashboard for the board you check every day, and an explorer for open-ended digging. A widget's **Open in explorer** action carries its filters and time range across.

Dashboards do not send alerts. Threshold alerts are set up in the [observability](/observability/overview/) pillars, and incident notifications come from [incident management](/incident-management/overview/).
