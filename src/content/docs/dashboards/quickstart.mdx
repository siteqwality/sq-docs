By the end of this guide you will have an uptime dashboard built from a template, with a failure-rate widget you added yourself, a `$region` variable, a saved default time range and a public link.

You need a paid plan and at least one [monitor](/getting-started/signup-and-first-monitor/). The template used here reads monitor data.

## 1. Create the dashboard from a template

<Steps>

1. Open **Dashboards** in the sidebar and choose **New dashboard**.

2. Pick **Template**. The gallery shows seven boards. Each is marked **Has data** or **No data yet** for your account. Choose **Uptime overview**.

</Steps>

You now have an ordinary dashboard with a monitor summary, a monitor grid, uptime, response time by region, failed checks, a slowest-monitors list, 30-day uptime bars, expiring certificates and domains, and open incidents. It is yours to edit.

## 2. Add a widget with the editor

You will chart the share of checks that failed. That takes two queries and a formula.

<Steps>

1. Choose **Edit** (or press `e`). The header turns into an edit bar.

2. Choose **Add widget**, search for **Time series** and click it to place it on the grid.

3. Open the new widget's menu and choose **Edit**. The widget editor opens as a drawer, with a live preview on top.

4. Set query **a** to source **Monitors** and measure **Checks**.

5. Add a second query. Set query **b** to source **Monitors** and measure **Failed checks**. Hide queries **a** and **b** so only the formula is drawn.

6. Add a formula: `b / a * 100`. Set its unit to **Percent** and its alias to `Failure rate`.

7. Leave the title empty to use the suggested one, or type your own. Close the drawer.

</Steps>

The widget is on the grid. Drag it to move it and drag its corner to resize it. Nothing is saved yet.

<Aside type="tip">
A formula divides, adds, subtracts and multiplies queries by their letters. Division by zero gives a gap rather than an error. See [queries, formulas and variables](/dashboards/queries/#formulas).
</Aside>

## 3. Add a variable

<Steps>

1. Still in edit mode, open **Settings** in the edit bar.

2. Add a variable named `region`. Bind it to source **Monitors**, field **Region**. Turn on multi select and **All**, and keep **All** as the default.

3. Apply the changes. A `Region` dropdown appears in the variables bar.

4. Open the menu of the response time by region chart and choose **Edit**. Add a filter on **Region** and choose `$region` as the value. Close the drawer.

</Steps>

Now the widget follows the dropdown. With **All** selected the filter is dropped, so every region shows. Pick one region and only that region remains. The selection is written to the URL as `var-region=us-east-1`.

## 4. Change the time

<Steps>

1. Open the time picker. Choose **7d**, or type `yesterday` or `Oct 1 - Oct 3` and press Enter.

2. Drag across a time chart to zoom in on a spike. Choose **Back** to return to the previous range.

3. Press `[` to step back one window and `]` to step forward.

</Steps>

A time change is a view. It lives in the URL and does not change the dashboard. To store a default range for everyone who opens the dashboard, set the range you want and choose **Save as default** while in edit mode.

## 5. Save

<Steps>

1. Choose **Save** in the edit bar, or press `Cmd+S`.

2. Open **Version history** from the actions menu. Your save is the newest entry, with a short summary of what changed.

</Steps>

If a teammate saved while you were editing, a conflict dialog explains what happened instead of overwriting their changes.

## 6. Share a public link

<Steps>

1. Choose **Share** in the header.

2. Create a public link. Choose which time ranges viewers may pick and which range the page opens with. Leave `region` selectable, or lock it to a value. Set a theme and, if you want one, an expiry date.

3. Copy the link. It looks like `https://app.siteqwality.com/share/d/<token>`.

4. Open it in a private window to see what viewers see.

</Steps>

Anyone with the link can see the data in the widgets. They cannot edit anything. Log stream and Trace list widgets do not appear on shared dashboards. To stop sharing, pause or revoke the link from the same dialog. See [sharing](/dashboards/sharing/).

## Prefer the API?

Everything above has an endpoint. This call creates the same board from the template:

```bash
curl -X POST https://api.siteqwality.com/dashboards/templates/uptime-overview \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "name": "Uptime overview" }'
```

The response is the full dashboard, including its `definition`. See [the API endpoints](/dashboards/reference/#api-endpoints).
