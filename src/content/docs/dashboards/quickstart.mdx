By the end of this guide you'll have a dashboard called `Service health` with two widgets (a metrics timeseries and a log stream), both sharing a 1-hour global time range that auto-refreshes every minute.

## 1. Create the dashboard

<Tabs syncKey="interface">
<TabItem label="Dashboard">

<Steps>

1. **Dashboards → New dashboard.**

2. **Name:** `Service health`. **Description:** `Live ops view`. **Global time range:** `Last 1 hour`. **Auto-refresh:** `60s`. Save.

</Steps>

</TabItem>
<TabItem label="API">

```bash
curl -X POST https://api.siteqwality.com/dashboard \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Service health",
    "description": "Live ops view",
    "global_time_range": { "type": "relative", "value": "1h" },
    "auto_refresh_seconds": 60
  }'
```

Note: dashboards can only be created by users (not API keys) because they need a `created_by` user ID. Use a session-based call from the dashboard for the create step, or generate a token tied to a real user.

</TabItem>
</Tabs>

## 2. Add a metrics widget

<Tabs syncKey="interface">
<TabItem label="Dashboard">

<Steps>

1. **Add widget → Timeseries.**

2. **Title:** `Request latency (avg)`. **Data source:** `Metrics`. **Metric:** `http.request.duration_ms`. Save. The widget charts the metric's average across all its series; dashboard widgets have no aggregation or group-by setting, so use the Metrics page for percentiles or a per-endpoint split.

</Steps>

</TabItem>
<TabItem label="API">

```bash
curl -X POST https://api.siteqwality.com/dashboard/$DASHBOARD_ID/widget \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Request latency (avg)",
    "widget_type": "timeseries",
    "data_source": "metrics",
    "query_config": { "metric_name": "http.request.duration_ms" },
    "layout": { "x": 0, "y": 0, "w": 6, "h": 4 }
  }'
```

</TabItem>
</Tabs>

## 3. Add a log stream widget

<Tabs syncKey="interface">
<TabItem label="Dashboard">

<Steps>

1. **Add widget → Log stream.**

2. **Title:** `Recent logs`. **Data source:** `Logs`. Save. The widget shows the newest log lines in the dashboard's time range, across your whole account; it has no filters, so open the Logs page to narrow it down.

</Steps>

</TabItem>
<TabItem label="API">

```bash
curl -X POST https://api.siteqwality.com/dashboard/$DASHBOARD_ID/widget \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Recent logs",
    "widget_type": "log_stream",
    "data_source": "logs",
    "query_config": {},
    "layout": { "x": 6, "y": 0, "w": 6, "h": 4 }
  }'
```

</TabItem>
</Tabs>

## 4. Reorder widgets

Drag widgets around in the editor; the layout updates live. Or batch-update positions:

```bash
curl -X PUT https://api.siteqwality.com/dashboard/$DASHBOARD_ID/layout \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "widgets": [
      { "widget_id": "<id-1>", "x": 0, "y": 0, "w": 12, "h": 4 },
      { "widget_id": "<id-2>", "x": 0, "y": 4, "w": 12, "h": 4 }
    ]
  }'
```

This is the cheapest update path when you're rearranging multiple widgets at once.

<Aside type="tip">
For per-team or per-service dashboards, prefix the name: `[Platform] Service health`, `[Billing] Webhook deliveries`. Sidebars sort alphabetically and the prefix groups dashboards naturally.
</Aside>
