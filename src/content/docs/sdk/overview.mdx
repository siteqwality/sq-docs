The Site Qwality client SDK is a single browser-side package: **`@siteqwality/rum`**. It collects [Real User Monitoring](/observability/rum/overview/) data and, when a recording rule activates it, [session replay](/observability/replay/overview/). Every option and behaviour is in the [SDK reference](/sdk/v2/). SDK 1.x is retired and no longer accepts data; install SDK 2.

It is **not** a back-end ingestion library, and there are no Site Qwality logging or metrics libraries for back-end languages. Send back-end traces with an OpenTelemetry SDK over OTLP/HTTP, and send logs and metrics as JSON over HTTPS to their ingest endpoints. See [Observability](/observability/overview/).

## What it does

| Capture | Tier |
|---|---|
| Page views, load timing and Web Vitals (LCP, FCP, CLS, INP, TTFB) with attribution | Observe: every sampled session |
| Errors with message, stack, causes and breadcrumbs (known browser noise filtered) | Observe |
| Failed requests, frustration signals and custom events | Observe |
| Clicks, taps and form actions, successful requests, resource timings, console entries and long animation frames | Analyze: activated by a recording rule |
| DOM snapshots and mutations (rrweb) | Replay: activated by a Replay recording rule |

See [what is collected when](/sdk/v2/#what-is-collected-when) for the details.

The SDK can add a W3C `traceparent` header to fetch and XHR requests whose URLs match the application's [`trace_urls`](/observability/rum/how-to/remote-config/#network-capture) setting, linking a user's request to your back-end [traces](/observability/traces/overview/).

## Install

### NPM

```bash
npm install @siteqwality/rum
```

### CDN

Paste the [CDN snippet](/sdk/v2/#cdn-snippet) into your page's `<head>`. It loads `https://cdn.siteqwality.com/rum/v2/sdk.min.js` asynchronously, queues your calls and captures early errors until the SDK arrives.

## Initialize

```javascript
import { SiteQwalityRUM } from '@siteqwality/rum';

SiteQwalityRUM.init({
  applicationId: 'abc123',          // from RUM application
  clientToken: 'pub_def456',        // from RUM application (public token)
  version: '1.4.2',                  // your release (used for source-map matching)
});
```

`init` starts collection synchronously, and the Promise it returns (settled once remote config is applied or fails) never needs an `await`. A second call is ignored. With the npm package, calls to other methods before `init()` are ignored, except the opt-out methods. Every option is in the [SDK reference](/sdk/v2/#init-options).

No public method throws: invalid input is ignored and internal failures are swallowed.

## Public methods

The full list, including consent, opt-out, replay control and `getStatus()`, is under [public methods](/sdk/v2/#public-methods).

### `setUser(user)` / `clearUser()`

Identify the user. Call after login, or as soon as you know who's there.

```javascript
SiteQwalityRUM.setUser({
  id: 'usr_abc123',
  email: 'alice@example.com',
  name: 'Alice',
});
```

| Field | Required | Description |
|---|---|---|
| `id` | optional | Your internal user ID. Shown on the session, searchable, and used by `identified` recording rule conditions. |
| `email` | optional | User's email. Shown on the session and searchable, unless the application does not capture user emails. |
| `name` | optional | Display name, shown on the session. |
| `traits` | optional | Up to 20 string labels, such as `{ plan: 'pro' }`. Used by `attribute` recording rule conditions. |

The user attaches to every batch sent after the call, page views included. Each call replaces the previous user; call `clearUser()` on logout.

### `setGlobalAttribute(key, value)` / `removeGlobalAttribute(key)`

Attach a string attribute to every batch sent after the call, or stop attaching it.

```javascript
SiteQwalityRUM.setGlobalAttribute('plan', 'pro');
SiteQwalityRUM.removeGlobalAttribute('plan');
```

Up to 50 attributes, keys up to 128 characters, values up to 1,024 (longer values are cut) and 4 KB in all. Invalid input is ignored, never thrown.

### `addError(error, context?)`

Track a custom error in addition to auto-captured errors.

```javascript
try {
  await chargeCard();
} catch (err) {
  SiteQwalityRUM.addError(err, { feature: 'checkout', step: '3' });
  throw err;
}
```

| Param | Type | Description |
|---|---|---|
| `error` | any | An `Error`, or any other value (recorded as text, with no stack). |
| `context` | `Record<string, string>` | **Stored** with the error. `sq.fingerprint` sets your own grouping. Read the warning below before putting anything in here. |

Custom errors pass the same [error filtering](/sdk/v2/#error-filtering) as captured ones.

### `addAction(name, context?)`

Track a custom event, such as a business milestone. Custom events are recorded for every sampled session, whether or not a recording rule matched.

```javascript
SiteQwalityRUM.addAction('checkout_completed', { variant: 'A' });
```

| Param | Type | Description |
|---|---|---|
| `name` | `string` | Event name, up to 256 characters. Used by `event` recording rule conditions. |
| `context` | `Record<string, string>` | **Stored** with the event. Read the warning below before putting anything in here. |

<Aside type="danger" title="Do not put personal data in context">
The `context` argument of `addError` and `addAction` **is stored**, and so are user traits and global attributes. Global attributes can be used in [session filters](/observability/rum/reference/#filter-grammar).

Pass low-cardinality, non-personal labels only, as in the `{ feature: 'checkout', step: '3' }` example above.
</Aside>

### Naming clicks

Auto-captured clicks are attributed to the nearest link, button, form control or similar element at or above the click target, and recorded with a name (its `data-sq-action-name`, `aria-label` or text, up to 64 characters) and a stable selector. Set `data-sq-action-name` on an element (or an ancestor) to name its clicks yourself, or turn on [hiding element text in click names](/observability/rum/how-to/remote-config/#hiding-element-text-in-click-names) for the application. See [click names](/sdk/v2/#click-names).

## Behaviour worth knowing

- **Errors are filtered.** Known browser noise (ResizeObserver loop warnings, detail-less `Script error.`, errors raised entirely inside browser extensions) is dropped, identical errors within 5 seconds are folded into one, and each error is limited to 10 and then one every 10 seconds, with at most 500 per page load. Ingest applies the same noise rules. A dropped error never marks a session as errored, never triggers a recording rule and is never billed. Add your own with `ignoreErrors`, `denyUrls` and `beforeSend`. See [error filtering](/sdk/v2/#error-filtering).
- **Page views follow real URL changes.** A view is recorded only when the minimised URL changes, and carries `loading_type` (`initial_load`, `route_change` or `bfcache_restore`). Web Vitals always belong to the document's initial view. See [page views and Web Vitals](/sdk/v2/#page-views-and-web-vitals).
- **Sessions are shared by tabs and follow the user.** Only user input, the tab becoming visible and new page views keep a session alive; it ends after 15 minutes without them or 4 hours in all. See [sessions](/sdk/v2/#sessions).
- **Recording rules are evaluated in the browser**, when the config arrives and on every relevant input, with per-session sampling. The decision lasts for the rest of the session, in every tab. See [rule evaluation](/sdk/v2/#rule-evaluation).
- **Frustration signals.** A click carries at most one of `error_click`, `rage_click` or `dead_click`, in that order of precedence. Add `data-sq-no-frustration` to an element, or list selectors in the application settings, to exempt controls that draw rapid or no-op clicks by design from rage and dead clicks. See [frustration signals](/sdk/v2/#frustration-signals).
- **Delivery is bounded.** Batches are gzipped, retried with backoff, and capped by a hard request budget per session and page load. See [batching and delivery](/sdk/v2/#batching-and-delivery).

## TypeScript types

The SDK ships with TypeScript types:

```typescript
import type { InitOptions, UserContext } from '@siteqwality/rum';
```

Notable types:

- `InitOptions`: `init` argument shape.
- `UserContext`: `setUser` argument shape.
- `SdkStatus`: what `getStatus()` returns.
- `SqEvent`, `SqEventKind`: the event and kind `beforeSend` receives.

See [exported types](/sdk/v2/#exported-types).

## Pricing

The SDK is free; what costs is the data it sends. See [capture and billing](/sdk/v2/#capture-and-billing) and [Replay pricing](/observability/replay/overview/#pricing).

## Compatibility

- Modern browsers. The bundles target ES2020, and there's no IE11 support.
- The CDN bundle is a classic script that defines a single global, `window.SiteQwalityRUM` (it also works when loaded with `type="module"`). The replay recorder is a separate file, loaded only when needed, and browsers without `CompressionStream` load a small gzip fallback.
- The npm package is published as both ESM and CJS, with types. Transpile further via your bundler if you support older browsers.
