The SiteQwality client SDK is a single browser-side package: **`@siteqwality/rum`**. It collects [Real User Monitoring](/observability/rum/overview/) data and (when activated) [session replay](/observability/replay/overview/) segments.

It is **not** a back-end ingestion library. For back-end metrics/logs/traces, ship via the OTel SDK or direct HTTP to the ingestion endpoints. See [Observability](/observability/overview/).

## What it does

| Capture | Always-on | Activated by filter |
|---|---|---|
| Web Vitals (LCP, FCP, CLS, INP, TTFB) | yes | no |
| View counts, page loads | yes | no |
| Individual error events (message, stack) | yes | no |
| Aggregate error / action counts | yes | no |
| Click / keypress targets | no | yes |
| Resource timings (fetch/XHR) | no | yes |
| Long tasks (>50ms) | no | yes |
| DOM snapshots + mutations (rrweb) | no | yes (`capture_replay: true`) |

The SDK does not inject `traceparent` headers or otherwise participate in distributed tracing. To correlate RUM sessions with back-end traces, propagate your own IDs via `setUser` / custom attributes.

## Install

### NPM

```bash
npm install @siteqwality/rum
```

### CDN

```html
<script type="module" src="https://cdn.siteqwality.com/rum/v1/sdk.min.js"></script>
```

## Initialize

```javascript
import { SiteQwalityRUM } from '@siteqwality/rum';

await SiteQwalityRUM.init({
  applicationId: 'abc123',          // from RUM application
  clientToken: 'pub_def456',        // from RUM application (public token)
  service: 'web',                    // logical service name
  version: '1.4.2',                  // app version (used for source-map matching)
  env: 'prod',                       // 'prod' | 'staging' | 'dev'

  // Optional overrides for self-hosted SiteQwality
  apiBase: 'https://api.siteqwality.com',
  ingestBase: 'https://rum.siteqwality.com',
  replayBase: 'https://replay.siteqwality.com',
});
```

`init` is idempotent; calling it twice is a no-op.

## Public methods

### `setUser(user)`

Identify the user. Call after login, or as soon as you know who's there.

```javascript
SiteQwalityRUM.setUser({
  id: 'usr_abc123',
  email: 'alice@example.com',
  name: 'Alice',
});
```

| Field | Required | Description |
|---|---|---|
| `id` | optional | Your internal user ID. Indexed for filtering. |
| `email` | optional | User's email. |
| `name` | optional | Display name. |

User context attaches to all subsequent events and replay segments.

### `addError(error, context?)`

Track a custom error in addition to auto-captured errors.

```javascript
try {
  await chargeCard();
} catch (err) {
  SiteQwalityRUM.addError(err, { feature: 'checkout', step: '3' });
  throw err;
}
```

| Param | Type | Description |
|---|---|---|
| `error` | `Error` | Any JS Error. |
| `context` | `Record<string, string>` | Accepted for forward compatibility; **not attached to the event today**. |

### `addAction(name, context?)`

Track a custom action (click-equivalent business event).

```javascript
SiteQwalityRUM.addAction('checkout_completed', { variant: 'A' });
```

| Param | Type | Description |
|---|---|---|
| `name` | `string` | Action label. |
| `context` | `Record<string, string>` | Accepted for forward compatibility; **not attached to the event today**. |

## TypeScript types

The SDK ships with TypeScript types:

```typescript
import type { RumConfig, UserContext } from '@siteqwality/rum';
```

Notable types:

- `RumConfig`: `init` argument shape.
- `UserContext`: `setUser` argument shape.
- `RumMeasureEvent`, `RumDetailEvent`, `RumErrorEvent`: internal payload shapes (rarely needed).
- `SessionFilterRule`, `SdkConfig`: server-fetched config shape.

## Pricing

The SDK is free; what costs is the data it sends. See [RUM pricing](/observability/rum/overview/#pricing) and [Replay pricing](/observability/replay/overview/#pricing).

## Compatibility

- Modern browsers: Chrome, Firefox, Safari, Edge (last 2 versions).
- ES2020+ output. The CDN bundle is an ES module (`<script type="module">`).
- For older browsers, transpile via your bundler. The npm bundle is published as both ESM and CJS.

<Aside type="caution">
The SDK uses `crypto.randomUUID()`, `PerformanceObserver`, and `fetch`, all widely available since ~2020. There's no IE11 support.
</Aside>
