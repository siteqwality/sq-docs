> **SDK 1.x:** This page documents the legacy SDK. For SDK 2 installation, config CDN, Observe error billing, consent and replay v2, use the [SDK 2 guide](/sdk/v2/).

The Site Qwality client SDK is a single browser-side package: **`@siteqwality/rum`**. It collects [Real User Monitoring](/observability/rum/overview/) data and (when activated) [session replay](/observability/replay/overview/) segments.

It is **not** a back-end ingestion library, and there are no Site Qwality logging or metrics libraries for back-end languages. Send back-end traces with an OpenTelemetry SDK over OTLP/HTTP, and send logs and metrics as JSON over HTTPS to their ingest endpoints. See [Observability](/observability/overview/).

## What it does

| Capture | Always-on | Activated by a recording rule |
|---|---|---|
| Web Vitals (LCP, FCP, CLS, INP, TTFB) | yes | no |
| View counts, page loads | yes | no |
| Individual error events (message, stack; known browser noise filtered) | yes | no |
| Aggregate error / action counts | yes | no |
| Click targets and frustration signals | no | yes |
| Resource timings (fetch/XHR) | no | yes |
| Long tasks (>50ms) | no | yes |
| DOM snapshots + mutations (rrweb) | no | yes (`capture_replay: true`) |

SDK 1.x does not inject `traceparent` headers or otherwise participate in distributed tracing. SDK 2 can add a `traceparent` header to requests whose URLs match the application's [`trace_urls`](/observability/rum/how-to/remote-config/) setting; on 1.x, propagate your own IDs via `setUser` / custom attributes.

## Install

### NPM

```bash
npm install @siteqwality/rum@1.0.7
```

At the 2026-10-04 checkpoint, npm has 1.0.7; CDN `/rum/v1/` is reported to serve 1.1. SDK 1.1 options such as `ignoreErrors`, `beforeSend` and `recorderUrl` are not available in the 1.0.7 npm package. For SDK2, check the [release channels](/sdk/v2/#install) before choosing an install path.

### CDN

Paste the snippet from the [RUM quickstart](/observability/rum/quickstart/#2-install-the-sdk) into your page's `<head>`. It loads `https://cdn.siteqwality.com/rum/v1/sdk.min.js` asynchronously, queues your calls and captures early errors until the SDK arrives.

## Initialize

```javascript
import { SiteQwalityRUM } from '@siteqwality/rum';

SiteQwalityRUM.init({
  applicationId: 'abc123',          // from RUM application
  clientToken: 'pub_def456',        // from RUM application (public token)
  version: '1.4.2',                  // your release (used for source-map matching)
});
```

On CDN SDK 1.1, `init` is fire-and-forget. Collection starts synchronously, and the Promise it returns (settled once remote config is applied or fails) never needs an `await`. It is idempotent; calling it twice is a no-op. With the npm package, calls to other methods before `init()` are ignored. Every option, including `recorderUrl` for self-hosting the replay recorder, is in the [SDK reference](/sdk/reference/#init-options-rumconfig).

No public method throws: invalid input is ignored and internal failures are swallowed.

## Public methods

### `setUser(user)`

Identify the user. Call after login, or as soon as you know who's there.

```javascript
SiteQwalityRUM.setUser({
  id: 'usr_abc123',
  email: 'alice@example.com',
  name: 'Alice',
});
```

| Field | Required | Description |
|---|---|---|
| `id` | optional | Your internal user ID. Shown on the session, searchable, and used by `has_user` filters. |
| `email` | optional | User's email. Shown on the session and searchable. |
| `name` | optional | Display name. Kept in the browser, not sent. |

From SDK 1.0.6 the user attaches to every event recorded after the call, page views and vitals included, so the session shows its user even without detail capture. Call `setUser({})` on logout. Call after `init()`; calls made before it are ignored.

### `setGlobalAttribute(key, value)` / `removeGlobalAttribute(key)`

Attach a string attribute to every error and detail event recorded after the call, or stop attaching it. Call after `init()`; calls made before it are ignored. Added in 1.0.6.

```javascript
SiteQwalityRUM.setGlobalAttribute('plan', 'pro');
SiteQwalityRUM.removeGlobalAttribute('plan');
```

Up to 50 attributes, keys up to 128 characters and values up to 1,024 (longer values are cut). Invalid input is ignored, never thrown. Values are stored like `context` below, so the same warning applies. See the [SDK reference](/sdk/reference/#siteqwalityrumsetglobalattributekey-value).

### `addError(error, context?)`

Track a custom error in addition to auto-captured errors.

```javascript
try {
  await chargeCard();
} catch (err) {
  SiteQwalityRUM.addError(err, { feature: 'checkout', step: '3' });
  throw err;
}
```

| Param | Type | Description |
|---|---|---|
| `error` | any | An `Error`, or any other value (recorded with `String(value)` as the message and no stack). |
| `context` | `Record<string, string>` | **Stored.** Merged into the event's `custom_attributes` and retained for 30 days. Read the warning below before putting anything in here. |

Custom errors pass the same [error filtering](/sdk/reference/#error-filtering) as captured ones.

### `addAction(name, context?)`

Track a custom action (click-equivalent business event).

```javascript
SiteQwalityRUM.addAction('checkout_completed', { variant: 'A' });
```

| Param | Type | Description |
|---|---|---|
| `name` | `string` | Action label. |
| `context` | `Record<string, string>` | **Stored.** Merged into the event's `custom_attributes` and retained for 30 days. Read the warning below before putting anything in here. |

<Aside type="danger" title="Do not put personal data in context">
The `context` argument of `addError` and `addAction` **is stored**. The SDK merges it into the event's `custom_attributes`, a `Map(String, String)` column on the `rum_events` table, and it is retained for **30 days** on every plan, free and paid alike. Buying a larger RUM Analyze pack raises the number of sessions you can record, not how long their events are kept, so there is no way to make that window longer.

An earlier version of this page said `context` was "accepted for forward compatibility; not attached to the event today". That was wrong. If you have been passing user objects, email addresses, order contents or anything else that identifies a person, that data is in `rum_events` now and stays there until its 30-day window expires.

No dashboard screen or API response renders `custom_attributes` today. Do not treat that as a safeguard. The data is stored, it is readable by anyone with database access, and a future release may surface it in the product.

Global attributes from `setGlobalAttribute` are stored the same way.

Pass low-cardinality, non-personal labels only, as in the `{ feature: 'checkout', step: '3' }` example above.
</Aside>

### Naming clicks

Auto-captured clicks are attributed to the nearest link, button, form control or similar element at or above the click target, and named from it, including up to 30 characters of its text. Set `data-sq-action-name` on an element (or an ancestor) to name its clicks yourself, or turn on [hiding element text in click names](/observability/rum/how-to/remote-config/#hiding-element-text-in-click-names) for the application. See [click names](/sdk/reference/#click-names).

## Behaviour worth knowing

- **Errors are filtered.** Known browser noise (ResizeObserver loop warnings, detail-less `Script error.`, errors raised entirely inside browser extensions) is dropped, and each message is limited to 10 errors and then one every 10 seconds, with at most 500 per page load. The ingest server applies the same noise rules. A dropped error never marks a session as errored, never triggers a recording rule and is never billed. Add your own with `ignoreErrors` and `beforeSend`. See [error filtering](/sdk/reference/#error-filtering).
- **Page views follow real URL changes.** A view is recorded only when the sanitised URL changes, and carries `loading_type` (`initial_load` or `route_change`). Load timing is sent for the initial load only, and Web Vitals always belong to the document's initial view. See [page views and Web Vitals](/sdk/reference/#page-views-and-web-vitals).
- **Sessions follow the user, not the SDK.** Only user input, the tab becoming visible and new page views keep a session alive; it ends after 15 minutes without them or 4 hours in all. See [sessions](/sdk/reference/#sessions).
- **Recording rules are evaluated immediately**: when the config loads or refreshes, and after every sent error, Web Vital, action and `setUser`. The decision persists across page loads in the same tab. See [rule evaluation](/sdk/reference/#rule-evaluation).
- **Frustration signals.** A click carries at most one of `error_click`, `rage_click` or `dead_click`, in that order of precedence. Add `data-sq-no-frustration` to an element, or list selectors in the application settings, to exempt controls that draw rapid or no-op clicks by design from rage and dead clicks. See [frustration signals](/sdk/reference/#frustration-signals).

## TypeScript types

The SDK ships with TypeScript types:

```typescript
import type { RumConfig, UserContext } from '@siteqwality/rum';
```

Notable types:

- `RumConfig`: `init` argument shape.
- `UserContext`: `setUser` argument shape.
- `RumMeasureEvent`, `RumDetailEvent`, `RumErrorEvent`: payload shapes. `RumErrorEvent` is what `beforeSend` receives.
- `SessionFilterRule`, `SdkConfig`: server-fetched config shape.

## Pricing

The SDK is free; what costs is the data it sends. See [RUM pricing](/observability/rum/overview/#pricing) and [Replay pricing](/observability/replay/overview/#pricing).

## Compatibility

- Modern browsers: Chrome, Firefox, Safari, Edge (last 2 versions).
- ES2020+ output. The CDN bundle is a classic script that defines a single global, `window.SiteQwalityRUM` (it also works when loaded with `type="module"`). The replay recorder is a separate file, loaded only when needed.
- For older browsers, transpile via your bundler. The npm bundle is published as both ESM and CJS.

<Aside type="caution">
The SDK uses `crypto.randomUUID()`, `PerformanceObserver`, and `fetch`, all widely available since ~2020. There's no IE11 support.
</Aside>
