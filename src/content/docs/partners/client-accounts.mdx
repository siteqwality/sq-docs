A **client account** is one of your managed clients. You create it, you choose what it is entitled to, you build its monitors and its status page inside it, and you remove it when the engagement ends.

In the dashboard, **Manage → Clients** lets you add a client, see every client with its monitor counts, and open one to work inside it. Setting a client's bundle, reading its usage and removing it are API only.

Managing clients requires the **Admin** or **Super Admin** role. API keys and M2M clients are refused (see [Roles and access](/partners/overview/#roles-and-access)), so the API-only calls below take the dashboard sign-in session of an Admin, shown as `<admin-session-token>`.

## Create a client

<Steps>

1. **Create the account.** Go to **Manage → Clients**, click **+ Add client**, fill in the form and click **Create client**.

   | Field | Required | Notes |
   |---|---|---|
   | **Client name** | yes | Your label for the client, up to 128 characters. Not shown to the client and not client-editable. |
   | **Contact email** | yes | The client's real contact address. Must not be in use by any Site Qwality account, including your other clients, compared case-insensitively. |
   | **Contact name** | no | Free text, up to 300 characters. |

   The new client appears on the **Clients** page with its account ID under its name. That ID is the `$CLIENT_ACCOUNT_ID` used everywhere else.

2. **Give it a bundle**, or it stays on the free tier. See [Set a client's bundle](#set-a-clients-bundle).

3. **Build its monitoring** by [working inside the account](/partners/context-switching/) with `X-SQ-Account`.

</Steps>

### What creation does

| Does | Does not |
|---|---|
| Creates the account, its first user, a default notification group and an email channel pointed at the contact email | Send the contact a welcome email, or any email |
| Creates an identity-provider organization so a later invite has somewhere to land | Invite anybody or create a session |
| Records you as the account's partner | Create a payment method or a billing customer |

To give your client a login, ask us to invite them; they get an ordinary invitation then. You cannot invite them yourself, because [`/account` refuses](/partners/context-switching/#endpoints-that-refuse-the-header) the `X-SQ-Account` header.

The default notification group alerts the contact email, so an outage on your client's site reaches your client. To hear first, change that group inside the client account before you build monitors, or add yourself alongside them.

## List your clients

The **Clients** page lists them newest first, with each client's account ID, contact, monitor count (and how many are down) and status. A paused monitor counts toward the total but never as down.

Removed clients are absent, so the list is a fair basis for reconciling your invoice.

## Set a client's bundle

```bash
curl -X PUT https://api.siteqwality.com/partner/accounts/$CLIENT_ACCOUNT_ID/plan \
  -H "Authorization: Bearer <admin-session-token>" \
  -H "Content-Type: application/json" \
  -d '{"bundle": "client_pro"}'
```

Pick one of two bundles; packs cannot be composed individually.

| | `client_standard` | `client_pro` |
|---|---|---|
| Check executions | 500K/month | 500K/month |
| Status page on the client's own domain (1 custom domain) | yes | yes |
| Fully branded status page (badge optional) | yes | yes |
| Synthetic browser checks | | 1,000 minutes/month |
| RUM (Observe) | | 25K sessions/month |
| RUM (Analyze) | | 1K sessions/month |
| Session replay | | 1K sessions/month |

`client_pro` is everything in `client_standard` plus the rows below it. A client set up while bundles included White-Label keeps that unit when you set its bundle again.

The response tells you what changed. Moving a client from `client_standard` to `client_pro` grants the four packs Pro adds:

```json
{
  "data": {
    "account_id": "0f3c9a1e-...",
    "bundle": "client_pro",
    "packs": [ { "pack_id": "...", "product": "uptime", "name": "500K Check Executions" } ],
    "granted": 4,
    "cancelled": 0
  }
}
```

Setting the bundle a client is already on grants nothing, cancels nothing and moves no billing date (`granted` and `cancelled` are both `0`), so re-sending it is safe.

Only the bundle's own entitlements are added and removed. Anything our staff granted the client stays.

## Check a client's usage

```bash
curl https://api.siteqwality.com/partner/accounts/$CLIENT_ACCOUNT_ID/usage \
  -H "Authorization: Bearer <admin-session-token>"
```

This returns per-product counters in each product's customer-facing unit, matching what the client sees on their own **Usage** page.

```json
{
  "data": {
    "account_id": "0f3c9a1e-...",
    "products": [
      {
        "product": "uptime",
        "current_usage": 128400,
        "quota_limit": 500000,
        "hard_stopped": false,
        "unit": "executions",
        "period": "2026-08"
      }
    ]
  }
}
```

Read each product's own `period`; there is no account-wide period. A product the client has never used has no row. `hard_stopped` means that product has stopped serving for the client because the quota is exhausted.

## Remove a client

<Aside type="danger" title="Removal cannot be undone, and the contact address stays taken">
Removal stops everything in the client's account. A removed client's contact address stays in use, so you cannot create a new client with it; if you removed a client by mistake or are re-onboarding the same contact, contact us rather than using a second address.
</Aside>

Removal is API only:

```bash
curl -X DELETE https://api.siteqwality.com/partner/accounts/$CLIENT_ACCOUNT_ID \
  -H "Authorization: Bearer <admin-session-token>"
```

Immediately after removal:

- the client's slot is freed, so you can add a replacement in the same minute,
- the client's checks stop running,
- the client's users can no longer sign in,
- the client can no longer be opened with `X-SQ-Account`, and
- the client disappears from the **Clients** page.

Removal is not erasure: the client's data is retained under the normal retention policy, and this endpoint is not a deletion request under GDPR or any other regime. If a client asks to be erased, contact us.

## Onboarding many clients at once

There is no bulk import: add each client from **Manage → Clients**, then set its bundle. If you are migrating dozens of clients from another platform and want the monitors seeded too, talk to us before you start.
