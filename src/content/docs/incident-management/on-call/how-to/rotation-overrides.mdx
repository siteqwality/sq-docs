An **override** is a hard "user X is on call from time A to time B" entry that beats every layer in the schedule.

Overrides do *not* modify the underlying rotation. Once the override expires, the rotation continues as if it never happened.

Overrides go on an existing [on-call schedule](/incident-management/on-call/quickstart/).

## Add an override

<Tabs syncKey="interface">
<TabItem label="Dashboard">

<Steps>

1. Open the schedule and click **Add override** beside **Overrides**.

2. Pick the **User** to put on call, then the **Start At** and **End At** times.

3. Click **Add Override**.

</Steps>

</TabItem>
<TabItem label="API">

With an [API key](/getting-started/account-and-team/#generate-api-keys) exported as `SITEQWALITY_API_KEY`, and the schedule's `id` from `GET /on_call_schedule` as `SCHEDULE_ID`:

```bash
curl -X POST https://api.siteqwality.com/on_call_schedule/$SCHEDULE_ID/override \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "user_id": "33333333-aaaa-4bbb-9ccc-ffffffffffff",
    "start_at": "2026-12-22T09:00:00Z",
    "end_at": "2027-01-02T09:00:00Z"
  }'
```

`user_id` takes a user ID that `GET /account/info` lists. Times are RFC 3339 with timezone. The schedule's own timezone doesn't apply to override timestamps; they're absolute.

</TabItem>
</Tabs>

## Common patterns

- **Vacation cover:** one override for the whole week. Carol takes over from Alice 09:00 Monday through 09:00 the following Monday.
- **Swap days:** two overrides, one calendar day each, so each engineer takes the other's day.
- **Patch a gap in a layer:** a layer with `effective_from: 2026-06-01` doesn't apply before then. Add an override covering the period until the layer starts.

## Overlapping overrides

If two overrides cover the same time, the **most recently created one wins**. Don't rely on this; delete the earlier one before adding a conflicting one. Overrides cannot be edited, so to shorten one, delete it and add it again with the new times.

## Removing an override

<Tabs syncKey="interface">
<TabItem label="Dashboard">

In the schedule's **Overrides** list, open the row's actions menu and choose **Delete override**.

</TabItem>
<TabItem label="API">

`OVERRIDE_ID` is the override's `id`, from `GET /on_call_schedule/$SCHEDULE_ID/override`.

```bash
curl -X DELETE https://api.siteqwality.com/on_call_schedule/$SCHEDULE_ID/override/$OVERRIDE_ID \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY"
```

</TabItem>
</Tabs>

You can delete an override that is in effect. The next page routes per the underlying layers.
