By the end of this guide you'll have a one-time maintenance window scheduled for Friday, January 15, 2027, 14:00–14:30 UTC, that silences any monitor tagged `service:api`.

## 1. Tag your monitors

If your monitors aren't tagged yet:

<Tabs syncKey="interface">
<TabItem label="Dashboard">

Open the monitor and choose **Edit monitor**. In the **Monitor** section, add `service:api` under **Tags**, then click **Save**.

</TabItem>
<TabItem label="API">

With an [API key](/getting-started/account-and-team/#generate-api-keys) exported as `SITEQWALITY_API_KEY`, and the monitor's `id` from `GET /http/jobs` as `JOB_ID`:

```bash
curl -X PUT https://api.siteqwality.com/http/job/$JOB_ID \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "tags": ["service:api"] }'
```

`tags` replaces the monitor's whole list, so include any tags it already has.

</TabItem>
</Tabs>

## 2. Create the window

<Tabs syncKey="interface">
<TabItem label="Dashboard">

<Steps>

1. Go to **Respond → Notifications**, click **Maintenance windows**, then **+ Add Maintenance Window**.

2. Configure:
   - **Name:** `Friday API deploy`.
   - **Tags:** `service:api`.
   - **Schedule Type:** **One-time**.
   - **Start:** `2027-01-15 14:00`. **End:** `2027-01-15 14:30`. The pickers use your browser's time zone, so enter the local time for 14:00–14:30 UTC.

3. Click **Create Window**.

</Steps>

</TabItem>
<TabItem label="API">

With an [API key](/getting-started/account-and-team/#generate-api-keys) exported as `SITEQWALITY_API_KEY`:

```bash
curl -X POST https://api.siteqwality.com/maintenance_windows \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Friday API deploy",
    "tags": ["service:api"],
    "schedule_type": "one_time",
    "starts_at": "2027-01-15T14:00:00Z",
    "ends_at": "2027-01-15T14:30:00Z"
  }'
```

The response has `is_currently_active: false` until the window starts.

</TabItem>
</Tabs>

## 3. Verify

The window appears on the **Maintenance Windows** page as **Scheduled**, then **Active** while it runs and **Ended** after. To see which monitors it covers, open it with **Edit window**: the form lists them under **Held now**.

To test suppression, break a monitor during the window: the check still shows `failure` in recent results, but no notification goes out while the window is active.

## 4. (Recommended) Publish on the status page

To tell customers, also [publish a status page maintenance](/status-pages/how-to/publish-maintenance/). It is separate from the maintenance window, which only holds internal paging.
