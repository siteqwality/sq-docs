By the end of this guide you'll have a one-time maintenance window scheduled for Friday 14:00–14:30 UTC that silences any monitor tagged `service:api`.

## Prerequisites

- One or more monitors tagged with `service:api`. Tags are set in the monitor form, or as the `tags` array through the API.

## 1. Tag your monitors

If your monitors aren't tagged yet:

<Tabs syncKey="interface">
<TabItem label="Dashboard">

Open the monitor and choose **Edit monitor**. In the **Monitor** section, add `service:api` under **Tags**, then click **Save**.

</TabItem>
<TabItem label="API">

```bash
curl -X PUT https://api.siteqwality.com/http/job/$JOB_ID \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "tags": ["service:api", "env:prod"] }'
```

</TabItem>
</Tabs>

## 2. Create the window

<Tabs syncKey="interface">
<TabItem label="Dashboard">

<Steps>

1. Go to **Respond → Notifications**, click **Maintenance windows**, then **+ Add Maintenance Window**.

2. Configure:
   - **Name:** `Friday API deploy`.
   - **Tags:** `service:api`.
   - **Schedule Type:** **One-time**.
   - **Timezone:** `UTC`.
   - **Start:** `2026-05-10 14:00`. **End:** `2026-05-10 14:30`.

3. Click **Create Window**.

</Steps>

</TabItem>
<TabItem label="API">

```bash
curl -X POST https://api.siteqwality.com/maintenance_windows \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Friday API deploy",
    "tags": ["service:api"],
    "schedule_type": "one_time",
    "starts_at": "2026-05-10T14:00:00Z",
    "ends_at": "2026-05-10T14:30:00Z"
  }'
```

</TabItem>
</Tabs>

The response includes `is_currently_active: false` (assuming the window is in the future) and confirms the start/end timestamps in RFC 3339.

## 3. Verify

The window appears on the **Maintenance Windows** page with a status badge. The card view shows:

- **Scheduled**: in the future.
- **Active**: happening now.
- **Ended**: already over.

The list view shows **Active** or **Inactive**.

When the window goes active, any matching monitor's status badge in the dashboard gets a "Maintenance" overlay. Notifications are suppressed automatically.

<Aside type="tip">
You can verify suppression by manually breaking a monitor during an active window. The check still runs and shows `failure` in recent results, but no notifications fire.
</Aside>

## 4. (Recommended) Publish on the status page

For customer-visible maintenance, also create a status-page maintenance entry. See [Publish a status page maintenance](/status-pages/how-to/publish-maintenance/). The two objects are independent: the maintenance window suppresses internal paging, the status page maintenance shows "Scheduled" cards to customers.
