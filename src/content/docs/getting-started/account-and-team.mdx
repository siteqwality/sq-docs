Once you have an account, there are a handful of one-time setup steps that pay off the moment something breaks. Do them now, not at 3am.

The **Get started** checklist in the dashboard sidebar tracks your setup progress. Click its **X** to dismiss it permanently for your user. It stays hidden after signing out and back in, including on other browsers and devices. Dismissing it does not affect your teammates' checklists.

## Secure your sign-in

Open **Account → Security** to add a passkey, set up an authenticator app, or manage your password. See [Sign-in and security](/getting-started/sign-in-and-security/) for email codes, recovery codes and account recovery.

## Invite your team

<Steps>

1. Open **Settings → Users**.

2. Click **Invite User**, enter their email, and pick the role they'll join with (defaults to **Member**). Inviting someone as Admin, Billing Admin, or Super Admin requires you to be a Super Admin yourself. To invite a group, choose **Invite several people** and paste up to 25 addresses (one per line, or separated by commas).

3. Invites expire after **14 days**. Pending invites stay listed in the same table with **Resend** and **Cancel** actions: Resend re-sends the original link and resets the expiry clock (including for already-expired invites); cancelling kills the link.

4. Roles, changeable later by any Super Admin from the dropdown in the Users table:
   - **Super Admin**: everything, including billing, role assignment, and SSO/SCIM. Multiple people can hold it. The account's original user is always a Super Admin and cannot be demoted or deleted.
   - **Admin**: team and credential management (invites, API keys, integrations, the audit log) and deleting escalation policies, on-call schedules and services: everything except billing, roles, and SSO/SCIM.
   - **Member**: full product access (monitors, incidents, dashboards), but no team, credential, or billing management, and no deleting escalation policies, on-call schedules or services. Members see integrations with their credentials masked but cannot add, change or remove them. New users start here.
   - **Auditor**: read-only across the product, plus access to the [audit log](/enterprise/audit-log/). An auditor can still manage their own contact methods and notification rules. For compliance reviewers who should see everything and change nothing else.
   - **Viewer**: read-only, except that a viewer can acknowledge and resolve incidents and manage their own contact methods and notification rules. Viewers cannot read the audit log.

</Steps>

<Aside type="caution">
Pending invites count toward your plan's seat limit immediately, not on acceptance. Expired invites stop counting on their own, and cancelling frees the seat right away. Free accounts have 3 seats.
</Aside>

Directory-managed teams should map IdP groups to the exact role IDs in [SCIM role mapping](/enterprise/scim/). Unknown names become Member. The account's original user cannot be deprovisioned.

## Set up your contact methods

A *contact method* is **how you personally** can be reached, whether that's your email, your phone for SMS, or a Slack DM. Distinct from a notification *channel*, which is account-level.

Each user manages their own contact methods in their personal settings, under **Notifications → Contact methods**. Admins can also manage other users' contact methods. Available types:

| Type | What it is |
|---|---|
| `email` | An email address. |
| `sms` | A phone number. There is no verification code, so check the number when you add it. |
| `slack_dm` | A Slack bot token and a channel or user ID that you paste in. It does not use the Slack integration. |

None are created for you, and there are no phone calls.

Once contact methods exist, set up **notification rules** to define which method fires for which urgency:

- *High* urgency: incidents with severity `critical` or `major`.
- *Low* urgency: incidents with severity `minor`.

A rule has an urgency, a contact method, and an optional `delay_minutes`. Stack multiple rules at increasing delays for personal escalation: SMS at 0 min, Slack DM at 5 min, email at 15 min. A user with no rule for an incident's urgency is not paged.

See the [Notification rules how-to](/incident-management/notifications/how-to/notification-rules/) for the full setup.

## Generate API keys

Anything you can do in the dashboard, you can do via the API. Generate a key under **Settings → API keys**.

<Steps>

1. **Settings → API keys → New key.**

2. Name it after where it'll be used (`local-dev`, `terraform-prod`, `ci`). One key per use case so you can rotate them independently.

3. Copy the value when shown. It's only displayed once, so store it in your secrets manager.

4. Use it as a Bearer token:

   ```bash
   curl https://api.siteqwality.com/http/jobs \
     -H "Authorization: Bearer <your API key>"
   ```

</Steps>

Keys belong to the account, not the user. Revoke immediately if leaked. Rotating a key ends the old one at once, so deploy the new value right away.

<Aside type="tip">
An API key with no scopes can do everything the account can, so give each key only the scopes it needs. For automation that should be limited to specific resources, or that a third party operates, use an [M2M API client](/enterprise/api-clients/) instead: scoped permissions, short-lived tokens, built-in rotation, and immediate revocation.
</Aside>

Whichever you use, every change either one makes is recorded in the [audit log](/enterprise/audit-log/).

## Configure billing

<Steps>

1. **Settings → Billing** to see what you're on and what's available.

2. **Change plan** flips you between tiers. Upgrades are immediate; downgrades take effect at the end of the current billing cycle.

3. **Customer portal** opens the Stripe-hosted portal where you can update payment methods, download invoices, and cancel.

</Steps>

Usage-relevant counters (monitor count, ingested logs/metrics/traces volume, RUM session count) live under **Settings → Usage**. Hard limits are enforced at the API layer, so you'll get a `403 Forbidden` if a request would push you over. Telemetry is the exception: past the allowance and its 10% grace buffer, the ingest endpoints still answer with a success status, but logs, metrics and traces are not stored.

## Set up integrations early

The rest of these docs assume Slack/Teams/Discord/Telegram/webhook integrations are already connected if you reference them. Connect the ones you use under **Manage → Integrations** before you wire monitors to them. See [Integrations overview](/integrations/overview/) for the per-tool setup steps.
