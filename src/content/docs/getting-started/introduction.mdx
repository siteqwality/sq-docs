Every engineering team duct-tapes the same four tools together: uptime monitoring, observability (metrics + logs + traces + RUM), on-call paging, and a public status page. SiteQwality combines all four into a single product, billed per seat instead of per gigabyte.

If you're tired of stitching Pingdom + Datadog + PagerDuty + Statuspage and watching the invoices climb in lock-step with your traffic, you're in the right place.

## What's in the platform

<CardGrid>
  <Card title="Uptime monitoring" icon="approve-check">
    HTTP, SSL/TLS, DNS, cron heartbeats, and full-browser synthetic checks, run on a schedule from AWS us-east-1, as often as every 30 seconds on paid plans.
  </Card>
  <Card title="Observability" icon="bars">
    Metrics, logs, traces, RUM, and session replay. One query language across all five.
  </Card>
  <Card title="Incident response" icon="warning">
    Incidents, on-call rotations, escalation policies, and notifications across email, SMS, Slack, Teams, Discord, Telegram, and webhooks.
  </Card>
  <Card title="Public status pages" icon="rocket">
    Branded, custom-domain status pages with components, scheduled maintenance, and email subscribers.
  </Card>
</CardGrid>

## How the docs are organised

Each product area has the same shape:

- **Overview**: what the feature is, when to reach for it, and how it relates to the rest of the platform.
- **Quickstart**: the fastest copy-pasteable path to first success.
- **How-to guides**: task-shaped recipes ("rotate an on-call schedule," "add a custom domain to a status page").
- **Reference**: every field on every object, with defaults and constraints.

The [API Reference](/api-reference/) is auto-generated from the live Rust handlers, so it's always in sync with what the API actually does.

## A note on plans

Most features in these docs work on the free plan. A few are paid: sub-minute check intervals, custom status-page domains, and session replay. Where that's the case the relevant page calls it out in an `Aside`.

Checks run from one location, AWS `us-east-1`. Additional check locations are on the roadmap and are not available today, on any plan. See [check locations](/uptime-monitoring/overview/#regions).
