By the end of this guide you'll have a public status page at `https://statuspage.siteqwality.com/<account-id>/<page-id>` that shows an HTTP check, carries your logo and brand color, and has one published incident. You need an existing HTTP check ([create one](/uptime-monitoring/http-checks/quickstart/) if you don't have one).

## 1. Create the page

<Tabs syncKey="interface">
<TabItem label="Dashboard">

<Steps>

1. Go to **Manage → Status Pages** and click **+ Create status page**.

2. Set the **Name**, e.g. `Acme Cloud`. Subscriber email uses it; the public page shows the **Page Title** you set when you [brand the page](#3-brand-the-page).

3. Click **Add**, then click the new page in the list to open it. Its public URL is shown at the top.

</Steps>

</TabItem>
<TabItem label="API">

With an [API key](/getting-started/account-and-team/#generate-api-keys) exported as `SITEQWALITY_API_KEY`:

```bash
curl -X POST https://api.siteqwality.com/status_page \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "friendly_name": "Acme Cloud" }'
```

Returns the new page's `id`. Export it as `STATUS_PAGE_ID` for the next steps.

</TabItem>
</Tabs>

## 2. Add components

A *component* is a public-facing label for one of your monitors. Here you attach HTTP and browser checks; heartbeats and components whose status you set yourself are added on the **Layout** tab (see [Group and order status page components](/status-pages/how-to/organize-components/)).

<Tabs syncKey="interface">
<TabItem label="Dashboard">

<Steps>

1. On the page, open the **Monitors** tab and click **Add Monitor**. For a browser check, use the **Browser Checks** tab and **Add Browser Check**.

2. Pick the check under **HTTP Site** (**Browser Check** for a browser check) and give it a public **Name** if the internal one is too technical (`prod-api-eu-west-1` → `API`). Click **Add**.

3. Optionally click the pencil on its row, set an **SLA Target (%)** (e.g. `99.9`) and click **Edit**. For an HTTP check, the page compares the uptime over the range the visitor picked (7, 30, 60 or 90 days) with this target.

</Steps>

Repeat for each monitor you want public.

</TabItem>
<TabItem label="API">

`$HTTP_JOB_ID` and `$BROWSER_CHECK_ID` are your checks' ids.

```bash
# Attach an HTTP check
curl -X POST https://api.siteqwality.com/status_page/$STATUS_PAGE_ID/http_job/$HTTP_JOB_ID \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "friendly_name": "API" }'

# Attach a browser check, if you have one
curl -X POST https://api.siteqwality.com/status_page/$STATUS_PAGE_ID/browser_check/$BROWSER_CHECK_ID \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "friendly_name": "Checkout flow" }'
```

</TabItem>
</Tabs>

## 3. Brand the page

<Tabs syncKey="interface">
<TabItem label="Dashboard">

<Steps>

1. On the page, open the **Branding** tab.

2. Under **Images**, click **Upload** next to **Logo** and pick your file (PNG, JPEG, SVG or WebP, up to 2 MB). Add a **Dark theme logo** the same way if your logo needs one. Each file is saved as soon as it uploads.

3. Under **Theme**, pick a **Default Theme** (**Light**, **Dark**, or **System (auto)** to follow the visitor's preference), and set the **Primary Color** (`#RRGGBB`) for the page title and the **Accent Color** for links and the Subscribe button.

4. Under **Page Info**, set a **Page Title** (browser tab) and optional **Header Text** and **Footer Text**.

5. Click **Save Settings**.

</Steps>

</TabItem>
<TabItem label="API">

Upload the logo first, then save its key with the other branding fields.

```bash
# 1. Get a presigned upload URL for the logo
UPLOAD=$(curl -s -X POST https://api.siteqwality.com/status_page/$STATUS_PAGE_ID/branding/upload \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "file_type": "logo",
    "content_type": "image/png",
    "file_size_bytes": 24576
  }')

UPLOAD_URL=$(echo "$UPLOAD" | jq -r .upload_url)
S3_KEY=$(echo "$UPLOAD" | jq -r .s3_key)

# 2. PUT the bytes directly to S3
curl -X PUT "$UPLOAD_URL" \
  -H "Content-Type: image/png" \
  --data-binary @logo.png

# 3. Save the s3_key + branding fields
curl -X PUT https://api.siteqwality.com/status_page/$STATUS_PAGE_ID/branding \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d "{
    \"page_title\": \"Acme Cloud Status\",
    \"default_theme\": \"system\",
    \"logo_s3_key\": \"$S3_KEY\",
    \"primary_color\": \"#0066ff\",
    \"accent_color\": \"#00ccaa\"
  }"
```

</TabItem>
</Tabs>

## 4. Publish your first incident

Create an incident by hand to confirm the page shows it. Incidents also reach a page when you publish an existing one or a [service](/incident-management/services/overview/) publishes one it opened automatically.

<Tabs syncKey="interface">
<TabItem label="Dashboard">

<Steps>

1. On the status page, open the **Incidents** tab and click **Report Incident**.

2. **Title:** `Investigating elevated API latency`. **Severity:** **Minor**. The incident starts as investigating.

3. In **Initial Update**, paste: `Our monitoring detected increased latency on the API. We're looking into it now.` Optionally pick the **Affected Monitors**.

4. Click **Report Incident**. The incident appears on the public page within about a minute.

</Steps>

</TabItem>
<TabItem label="API">

```bash
# Create the incident on the status page
curl -X POST https://api.siteqwality.com/status_page/$STATUS_PAGE_ID/incident \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "title": "Investigating elevated API latency",
    "severity": "minor",
    "message": "Our monitoring detected increased latency on the API. We are looking into it now.",
    "affected_http_job_ids": ["<http-job-id>"]
  }'
```

Returns the incident's `id`. Export it as `INCIDENT_ID` for step 6.

</TabItem>
</Tabs>

## 5. Confirm visitors can see it

Open `https://statuspage.siteqwality.com/<account-id>/<page-id>` in an incognito window. You should see:

- Your logo and brand colors.
- Each component with its current status (**Operational** with a green dot when healthy, **Down** in red when failing).
- The open incident at the top, with its updates newest first.
- For each HTTP check, a 90-day uptime bar chart and response-time percentiles. Browser checks show their current status and SLA label only.

Changes reach the page within about a minute, and an open page refreshes itself every 60 seconds.

## 6. Resolve the incident

<Tabs syncKey="interface">
<TabItem label="Dashboard">

Open the incident from the **Incidents** tab and click **Mark Resolved**. That posts a public **Resolved** update, emails the page's subscribers and closes the incident on the page. For a closing message of your own, pick **Resolved** under **Post Update** instead, write the message and click **Post Update**.

</TabItem>
<TabItem label="API">

```bash
# A resolved update closes the incident and emails confirmed subscribers
curl -X POST https://api.siteqwality.com/status_page/$STATUS_PAGE_ID/incident/$INCIDENT_ID/update \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "status": "resolved",
    "message": "Latency has returned to baseline."
  }'
```

</TabItem>
</Tabs>
