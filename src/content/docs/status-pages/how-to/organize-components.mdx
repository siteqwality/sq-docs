A status page lists its components in one flat list by default. With a **layout** you can split the list into named groups (for example `Public API`, `Dashboard`, `Third-party`), choose the order, add a line of explanation under a name, hide a component without detaching it, or show a component's status without the uptime history.

In the dashboard, open the status page and use the **Layout** tab: add and rename groups, move components with the arrows, the group menu or drag and drop, then **Save**. The rest of this page does the same through the API.

## Read the current layout

```bash
curl https://api.siteqwality.com/status_page/$STATUS_PAGE_ID/layout \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY"
```

The response has `ungrouped` (shown first, with no heading) and `groups`, each with its `components` in page order. Every component has `monitor_id`, `kind` (`http_job` or `browser_check`), `friendly_name`, `description`, `hidden` and `show_uptime`. Hidden components are included here so you can show them again.

## Save a layout

`PUT /status_page/{id}/layout` replaces the whole layout in one request.

```bash
curl -X PUT https://api.siteqwality.com/status_page/$STATUS_PAGE_ID/layout \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "ungrouped": [
      { "monitor_id": "<http-job-id>" }
    ],
    "groups": [
      {
        "name": "Public API",
        "description": "Everything customers integrate with.",
        "components": [
          { "monitor_id": "<http-job-id>", "description": "REST API, all regions" },
          { "monitor_id": "<browser-check-id>", "show_uptime": false }
        ]
      }
    ]
  }'
```

| Field | Where | Description |
|---|---|---|
| `groups[].id` | group | Send the id from a previous read to keep and rename or reorder a group. Leave it out to create one. |
| `groups[].name` | group | Required, at most 100 characters. |
| `groups[].description` | group | Optional, at most 500 characters. |
| `monitor_id` | component | A monitor already attached to this page. |
| `description` | component | Optional one line under the name, at most 200 characters. |
| `hidden` | component | `true` leaves the component off the public page and out of the headline. Default `false`. |
| `show_uptime` | component | `false` shows the status only, with no uptime bars, percentage or SLA badge. Default `true`. Browser checks never show uptime bars, so it changes nothing for them. |

Order is the order of the arrays, and a page holds at most 50 groups. The response is the saved layout.

What the request does with what it leaves out:

- A **group** you do not list is deleted. Its components move to the end of the ungrouped list.
- A **component** you do not list moves to the end of the ungrouped list. It keeps its description, `hidden` and `show_uptime`.
- A monitor that is not on the page, a group that is not on the page, or a monitor listed twice returns `400` and changes nothing.

<Aside type="caution">
A hidden component is not counted in the page headline. If it is down and hidden, the page can read **Operational**. Incidents and maintenance you post still show.
</Aside>

A monitor you attach later appears at the end of the ungrouped list until you move it.

## What visitors see

Ungrouped components come first, then each group in order with its name as the heading. A group whose components are all hidden does not appear. A page with no layout looks as it always did, except that HTTP and browser checks now sort together by name.

The [public API](/status-pages/reference/#public-status-page-api) carries the same information, so a page of your own can use it.
