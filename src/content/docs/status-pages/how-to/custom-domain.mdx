By default a status page lives at `https://statuspage.siteqwality.com/<account-id>/<page-id>`. A custom domain such as `status.yourcompany.com` serves it on your own subdomain, with a TLS certificate Site Qwality provisions through AWS Certificate Manager (ACM).

Each custom domain is a paid status page extra. See [plan limits](/getting-started/plan-limits/#status-pages).

## 1. Register the custom domain in Site Qwality

<Steps>

1. Open the status page in the dashboard and go to its **Custom Domain** tab.

2. Under **Domain**, enter your subdomain, e.g. `status.example.com`, and click **Set Up Domain**.

3. The page reloads with two CNAME records to add to your DNS provider, plus a status badge that starts at `pending_validation`.

</Steps>

Or via the API:

```bash
curl -X POST https://api.siteqwality.com/status_page/$STATUS_PAGE_ID/custom_domain \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "domain": "status.example.com" }'
```

The response includes:

```json
{
  "status_page_id": "abc123",
  "domain": "status.example.com",
  "status": "pending_validation",
  "cname_target": "abc123.custom.siteqwality.com",
  "acm_validation": {
    "name": "_xyz.status.example.com",
    "value": "_xyz.acm-validations.aws"
  },
  ...
}
```

## 2. Add both CNAME records

In your DNS provider (Cloudflare, Route53, NS1, etc.) add a **traffic CNAME** that points your subdomain at Site Qwality, and an **ACM validation CNAME** that proves to AWS you control the domain so it can issue the certificate:

| Record type | Name | Value | TTL |
|---|---|---|---|
| `CNAME` | `status` (i.e. `status.example.com`) | `<cname_target from step 1>` | `300` (or auto) |
| `CNAME` | `_xyz.status` (the `acm_validation.name`) | `_xyz.acm-validations.aws` (the `acm_validation.value`) | `300` |

<Aside type="caution">
If you use Cloudflare with the orange-cloud proxy, **set the traffic CNAME to "DNS only" (gray cloud)**. Cloudflare's proxy will break the upstream TLS handshake against ACM's certificate.
</Aside>

## 3. Wait for validation

The `status` field progresses through:

- `pending_validation`: DNS records not yet seen.
- `provisioning`: validation passed, certificate being issued.
- `active`: fully live; your domain serves the status page.
- `failed`: something went wrong; check `failure_reason` in the API response.

Refresh the dashboard or poll:

```bash
curl https://api.siteqwality.com/status_page/$STATUS_PAGE_ID/custom_domain \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY"
```

Total time is usually 5–15 minutes once both DNS records are in place.

## 4. Verify

Open `https://status.example.com` in a fresh browser. You should see:

- A valid TLS certificate (no warnings).
- Your branded status page.
- The default URL (`https://statuspage.siteqwality.com/<account-id>/<page-id>`) still works as a fallback.

Your domain also serves the page's [feeds, badge and embed script](/status-pages/how-to/feeds-badge-embed/). Any other path on it answers with a short "Page not found" page that links back to your status page.

## Removing a custom domain

On the **Custom Domain** tab, click **Remove Domain**. Through the API:

```bash
curl -X DELETE https://api.siteqwality.com/status_page/$STATUS_PAGE_ID/custom_domain \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY"
```

The domain stops serving at once. Deleting the status page removes its custom domain the same way. In either case, delete the two CNAME records from your DNS so they do not dangle.

## Notes

- Only one custom domain per status page.
- Apex domains (`example.com` with no subdomain) aren't supported because of the CNAME-at-apex restriction in DNS. Use a subdomain like `status` or `health`.
- The certificate auto-renews as long as the validation CNAME stays in place, so keep both records for as long as you use the domain.

## Domain health

Once the domain is live, Site Qwality checks every 6 hours that your hostname still points at the `cname_target` and that the certificate is issued and renewing. The **Custom domain** tab shows when it was last checked and when the certificate expires. If something is wrong it shows **Needs attention** with what to fix, such as a CNAME that was removed or now points elsewhere, or a renewal waiting on the validation record. The API returns the same in the `health` field.

## Email from your domain (optional)

With the page white-labeled, subscriber email carries your page's name, and it can also come from your domain, as `notifications@status.example.com`, signed for it. Add the third, optional CNAME the **Custom domain** tab shows under **Email from your domain**. Once the domain is live, Site Qwality checks the record every 15 minutes until it is verified, then every 6 hours. The API returns the same in the `sender` field.

Until the record is verified, or if it is later removed, subscriber email goes out from Site Qwality's address. Without white-label it always does.
