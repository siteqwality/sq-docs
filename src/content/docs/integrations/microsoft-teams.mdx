The Microsoft Teams integration posts alerts to a Teams channel through a Workflows webhook URL. Each alert is an Adaptive Card with a coloured title (red when a monitor goes down, green when it recovers) and a fact set: **Monitor**, **Status** and **URL** on every card, **Reason** when the check reported one, and **Started** and **Resolved** on a recovery. The card has no link back to Site Qwality.

<Aside type="caution" title="Office 365 Connectors no longer work">
Microsoft retired Office 365 Connectors in Teams in May 2026, so Incoming Webhook connector URLs (`outlook.office.com/webhook/...` or `*.webhook.office.com`) no longer deliver. Use a Workflows webhook as described below. If you have a Teams integration with a connector URL, create a new integration with a Workflows URL and point your notification channels at it.

Saving a connector URL is refused with a `400` that says so, and so is a Workflows URL on the retired `logic.azure.com` hosts.
</Aside>

## Set up

<Steps>

1. In Microsoft Teams, open the channel you want alerts posted to.

2. Open **Workflows** for the channel (from the channel's **More options (...)** menu, or the Workflows app) and choose the template **Post to a channel when a webhook request is received**.

3. Pick the team and channel, then finish the flow. Teams shows the flow's webhook URL. Copy it.

4. In Site Qwality, go to **Manage → Integrations** and click the **Microsoft Teams** card. Give the integration a name, paste the URL into **Workflows webhook URL** and click **Add**.

</Steps>

Or through the API, with [`POST /integration/microsoft_teams`](/api-reference/operations/add_microsoft_teams_integration/):

```bash
curl -X POST https://api.siteqwality.com/integration/microsoft_teams \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "friendly_name": "Ops Teams channel",
    "url": "<your Workflows webhook URL>"
  }'
```

<Aside type="note" title="Things to know about Workflows flows">
- A flow belongs to the person who created it. If they leave your organisation, the flow stops, so add a co-owner to the flow in Power Automate.
- On some Microsoft 365 plans, Microsoft turns off a flow that has had no successful run for 90 days. A channel for a quiet monitor can reach that, so check the flow if a channel has been silent for a long time.
- Your organisation must allow Workflows in Teams.
</Aside>

## Add it to a notification group

Integrations deliver nothing on their own. Alerts reach one once it is a channel in a notification group that your monitors use.

<Steps>

1. Go to **Respond → Notifications**. Click a group's name to open it, or click **Add group** to make a new one.

2. Under **Notifications**, click **Add Notification Method**. Set **Notification Type** to **Microsoft Teams** and choose this integration under **Integration**.

3. Click **Done editing**, then **Update Group** (**Create Group** for a new group).

</Steps>

Through the API, create the channel with [`POST /notification`](/api-reference/operations/create_notification/):

```bash
curl -X POST https://api.siteqwality.com/notification \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "notification_group_id": "<your-group-id>",
    "type": "microsoft_teams",
    "details": {
      "teams_integration_id": "<teams-integration-id>"
    }
  }'
```

The destination is implicit in the integration's webhook URL, so you don't specify a channel separately.

## What reaches Teams

HTTP monitors, browser checks, TLS and domain expiry warnings, page speed alerts, log, metric and trace alert rules, and RUM issues all post to Teams. Heartbeat (cron) monitors and DNS record changes do not post to Teams today, and incidents and escalations do not use Teams. See the [coverage table](/integrations/coverage/#microsoft-teams).

Each attempt waits up to 10 seconds and never follows a redirect. A deleted or refused workflow URL (`400`, `401`, `403`, `404`, `410`) or a redirect is recorded once as rejected and not retried. Other failures are tried up to three times in quick succession. There is no later retry.

## Multiple channels

For multiple Teams destinations, create one flow and one integration per channel. Then create one notification per integration.
