The Mattermost integration posts to a channel through an incoming webhook, using Mattermost's Slack-compatible attachment format. It works with self-hosted and Cloud instances alike, since the webhook URL is yours.

## What you need

<Steps>

1. In Mattermost, go to **Integrations → Incoming Webhooks**.

2. **Add Incoming Webhook**, pointed at the channel you want alerts in.

3. Copy the URL. It looks like `https://your-mattermost.example.com/hooks/...`.

</Steps>

## Connect it

In the dashboard, **Integrations → Add Integrations → Mattermost**. Name it, paste the URL into **Webhook URL**, and click **Add**. Or via the API:

```bash
curl -X POST https://api.siteqwality.com/integration/mattermost \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "friendly_name": "Acme Mattermost",
    "url": "https://your-mattermost.example.com/hooks/xxxxxxxx"
  }'
```

The request field is `url`; the stored and returned field is `mattermost_webhook_url`. Both fields are required and must be non-empty, and the URL is not validated or tested at save time.

<Aside type="caution" title="The webhook URL is readable after saving">
The Mattermost webhook URL is **echoed back in full** by `GET /integration` and recorded verbatim on each delivery record. Anyone with read access to your integrations can post to that channel. Regenerate the webhook in Mattermost if that access changes.
</Aside>

## Create a channel

```bash
curl -X POST https://api.siteqwality.com/notification \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "notification_group_id": "<your-group-id>",
    "type": "mattermost",
    "details": { "mattermost_integration_id": "<mattermost-integration-id>" }
  }'
```

## Message format

Messages post as `Site Qwality` with a Slack-style attachment: a colored bar, a title, and fields for the monitor details.

| Event | Color |
|---|---|
| Monitor down | red (`#ff0000`) |
| Monitor recovered | green (`#36a64f`) |
| Domain expiry warning | amber (`#ffcc00`) |

## Delivery behavior

<Aside type="caution" title="A failed send is not retried later">
Mattermost rides the shared platform-webhook transport: a send is tried up to 3 times in quick succession, each with a 15 second timeout, and any non-2xx response counts as a failure. After that the alert is not retried. A send that ends with an error response shows as failed in the channel's alert history; a send that runs out of time can be lost with no record.

If Mattermost is your only alerting path for something that matters, pair it with a second channel.
</Aside>

## Limitations

Mattermost channels fire for **HTTP monitors, browser checks, domain expiry warnings, log, metric and trace alert rules, and RUM issues**. Heartbeat (cron) monitors, TLS expiry warnings, page speed alerts and DNS record changes do not reach Mattermost today: a Mattermost channel on a group used by those sources is skipped. Incidents and escalations do not use Mattermost. See the [coverage table](/incident-management/notifications/channels/#which-alerts-reach-which-channels).
