The Mattermost integration posts to a channel through an incoming webhook, using Mattermost's Slack-compatible attachment format. It works with self-hosted and Cloud instances alike, since the webhook URL is yours.

## What you need

<Steps>

1. In Mattermost, go to **Integrations → Incoming Webhooks**.

2. **Add Incoming Webhook**, pointed at the channel you want alerts in.

3. Copy the URL. It looks like `https://your-mattermost.example.com/hooks/...`.

</Steps>

## Connect it

In the dashboard, go to **Manage → Integrations** and click the **Mattermost** card. Name it, paste the URL into **Webhook URL**, and click **Add**.

Or through the API, with [`POST /integration/mattermost`](/api-reference/operations/add_mattermost_integration/):

```bash
curl -X POST https://api.siteqwality.com/integration/mattermost \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "friendly_name": "Acme Mattermost",
    "url": "https://your-mattermost.example.com/hooks/xxxxxxxx"
  }'
```

The request field is `url`; the stored field is `mattermost_webhook_url`. Both fields are required. The URL must use `https` on a public host, or the save is refused with a `400`. It is not test-sent at save time.

<Aside type="note" title="The webhook URL does not read back">
`GET /integration` shows the Mattermost webhook URL as its scheme and host only, such as `https://your-mattermost.example.com/****`, and delivery records show only the host. Keep your own copy if you need it again. To change it, add a new integration and delete the old one.
</Aside>

## Add it to a notification group

Integrations deliver nothing on their own. Alerts reach one once it is a channel in a notification group that your monitors use.

<Steps>

1. Go to **Respond → Notifications**. Click a group's name to open it, or click **Add group** to make a new one.

2. Under **Notifications**, click **Add Notification Method**. Set **Notification Type** to **Mattermost** and choose this integration under **Integration**.

3. Click **Done editing**, then **Update Group** (**Create Group** for a new group).

</Steps>

Through the API, create the channel with [`POST /notification`](/api-reference/operations/create_notification/):

```bash
curl -X POST https://api.siteqwality.com/notification \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "notification_group_id": "<your-group-id>",
    "type": "mattermost",
    "details": { "mattermost_integration_id": "<mattermost-integration-id>" }
  }'
```

## Message format

Messages post as `Site Qwality` with a Slack-style attachment: a colored bar, a title, and fields for the monitor details.

| Event | Color |
|---|---|
| Monitor down | red (`#ff0000`) |
| Monitor recovered | green (`#36a64f`) |
| Domain expiry warning | amber (`#ffcc00`) |

## Delivery behavior

<Aside type="caution" title="A failed send is not retried later">
Mattermost rides the shared platform-webhook transport. Each attempt waits up to 10 seconds, and a redirect is never followed. An answer no retry can change (`400`, `401`, `403`, `404`, `410` or a redirect) is recorded once as rejected, with the reason, and not retried. Any other error answer, or a connection that could not be made, is tried up to 3 times in quick succession and then recorded as failed. A send that times out after the request went out may have arrived, so it is not sent again: it is recorded as failed with that note. The attempts stop before the send's time limit, so the outcome is always recorded, but nothing is retried later.

If Mattermost is your only alerting path for something that matters, pair it with a second channel.
</Aside>

## Limitations

Mattermost channels fire for **HTTP monitors, browser checks, domain expiry warnings, log, metric and trace alert rules, and RUM issues**. Heartbeat (cron) monitors, TLS expiry warnings, page speed alerts and DNS record changes do not reach Mattermost today: a Mattermost channel on a group used by those sources is skipped. Incidents and escalations do not use Mattermost. See the [coverage table](/integrations/coverage/#mattermost).
