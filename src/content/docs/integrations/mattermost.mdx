The Mattermost integration posts to a channel through an incoming webhook, using Mattermost's Slack-compatible attachment format. It works with self-hosted and Cloud instances.

## What you need

<Steps>

1. In Mattermost, go to **Integrations → Incoming Webhooks**.

2. **Add Incoming Webhook**, pointed at the channel you want alerts in.

3. Copy the URL. It looks like `https://your-mattermost.example.com/hooks/...`.

</Steps>

## Connect it

In the dashboard, go to **Manage → Integrations** and click the **Mattermost** card. Name it, paste the URL into **Webhook URL**, and click **Add**.

Or through the API, with [`POST /integration/mattermost`](/api-reference/operations/add_mattermost_integration/):

```bash
curl -X POST https://api.siteqwality.com/integration/mattermost \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "friendly_name": "Acme Mattermost",
    "url": "https://your-mattermost.example.com/hooks/xxxxxxxx"
  }'
```

The URL must use `https` on a public host. It is not test-sent at save time, and it never reads back in full, so keep your own copy; to change it, add a new integration and delete the old one.

## Add it to a notification group

Right after you add the integration, the dashboard offers to do this for you: choose a group or create one, choose which monitors alert that group (the ones that already do, every monitor, or ones you pick), then send a test. If you skipped it, **Route alerts** on the integration's card opens the same step. To do it by hand:

<Steps>

1. Go to **Respond → Notifications**. Click a group's name to open it, or click **Add group** to make a new one.

2. Under **Notifications**, click **Add Notification Method**. Set **Notification Type** to **Mattermost** and choose this integration under **Integration**.

3. Click **Done editing**, then **Update Group** (**Create Group** for a new group).

</Steps>

Through the API, create the channel with [`POST /notification`](/api-reference/operations/create_notification/):

```bash
curl -X POST https://api.siteqwality.com/notification \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "notification_group_id": "<your-group-id>",
    "type": "mattermost",
    "details": { "mattermost_integration_id": "<mattermost-integration-id>" }
  }'
```

## Message format

Messages post as `Site Qwality` with a Slack-style attachment: a colored bar, a title, and fields for the monitor details.

| Event | Color |
|---|---|
| Monitor down | red (`#ff0000`) |
| Monitor recovered | green (`#36a64f`) |
| Domain expiry warning | amber (`#ffcc00`) |

## Delivery behavior

A failed send can get up to 3 attempts in quick succession but is never retried later, and the outcome is always recorded. If Mattermost is your only alerting path for something that matters, pair it with a second channel. See [delivery guarantees](/incident-management/notifications/channels/#delivery-guarantees-by-channel).

## Limitations

Heartbeat (cron) monitors, TLS certificate alerts, page speed alerts and DNS record changes do not reach Mattermost. See the [coverage table](/integrations/coverage/#mattermost).
