Pushbullet pushes alerts to every device signed into your Pushbullet account. Alerts arrive as note pushes with the monitor status as the title.

## What you need

An **access token** from your Pushbullet account.

<Steps>

1. In Pushbullet, go to **Settings → Account**.

2. **Create Access Token.**

3. Copy the token.

</Steps>

## Connect it

In the dashboard, go to **Manage → Integrations** and click the **Pushbullet** card. Give it a name, paste the token into **Access Token** and click **Add**.

Or through the API, with [`POST /integration/pushbullet`](/api-reference/operations/add_pushbullet_integration/):

```bash
curl -X POST https://api.siteqwality.com/integration/pushbullet \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "friendly_name": "My devices",
    "access_token": "<pushbullet-access-token>"
  }'
```

Both fields are required and must be non-empty. The token is not verified against Pushbullet at save time.

The token is a secret: `GET /integration` never returns it, and it is redacted from the stored delivery record. `pushbullet_access_token` shows it as `****` followed by its last four characters (just `****` when it is shorter than 16 characters).

<Aside type="caution">
A Pushbullet account access token grants full access to the account, not just the ability to push. Create it on an account you are comfortable dedicating to alerting.
</Aside>

## Add it to a notification group

Integrations deliver nothing on their own. Alerts reach one once it is a channel in a notification group that your monitors use.

<Steps>

1. Go to **Respond → Notifications**. Click a group's name to open it, or click **Add group** to make a new one.

2. Under **Notifications**, click **Add Notification Method**. Set **Notification Type** to **Pushbullet** and choose this integration under **Integration**.

3. Click **Done editing**, then **Update Group** (**Create Group** for a new group).

</Steps>

Through the API, create the channel with [`POST /notification`](/api-reference/operations/create_notification/):

```bash
curl -X POST https://api.siteqwality.com/notification \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "notification_group_id": "<your-group-id>",
    "type": "pushbullet",
    "details": { "pushbullet_integration_id": "<pushbullet-integration-id>" }
  }'
```

## Message format

Each alert is a Pushbullet **note** push: a title carrying the monitor and its new status, and a body with the detail. There is no priority concept in Pushbullet, so outages and recoveries arrive identically as far as your device is concerned.

## Delivery behavior

Like Pushover, Pushbullet sends are **not** retried in-process, because a re-send would appear as a duplicate push. A single attempt is made. A 4xx answer is recorded as rejected. Any other failure fails the event, and it is run up to two more times, so a duplicate push is possible. If those runs fail too, the alert is dropped with no record in alert history.

## Limitations

Pushbullet channels fire for **HTTP monitors, browser checks, domain expiry warnings, log, metric and trace alert rules, and RUM issues**. Heartbeat (cron) monitors, TLS expiry warnings, page speed alerts and DNS record changes do not reach Pushbullet today: a Pushbullet channel on a group used by those sources is skipped. See the [coverage table](/integrations/coverage/#pushbullet).
