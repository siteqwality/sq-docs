The Discord integration uses an incoming webhook URL from a Discord channel. Site Qwality posts embeds with a coloured bar (red when a monitor goes down, green when it recovers) and named fields: **Monitor**, **Status** and **URL** on every alert, **Reason** when the check reported one, and **Started** and **Resolved** on a recovery. The embed has no link back to Site Qwality.

## Set up

<Steps>

1. In Discord, open the target channel's settings → **Integrations → Webhooks → New Webhook**.

2. Name it (`Site Qwality Alerts`), assign an avatar (optional), copy the **Webhook URL**.

3. In Site Qwality, go to **Manage → Integrations** and click the **Discord** card. Give the integration a name, paste the URL into **Webhook URL** and click **Add**.

</Steps>

Or through the API, with [`POST /integration/discord`](/api-reference/operations/add_discord_integration/):

```bash
curl -X POST https://api.siteqwality.com/integration/discord \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "friendly_name": "Discord ops",
    "url": "https://discord.com/api/webhooks/<id>/<token>"
  }'
```

The URL must be a Discord webhook URL (`https://discord.com/api/webhooks/...`), or the save is refused with a `400`. `GET /integration` shows it only as `https://discord.com/****`.

## Add it to a notification group

Integrations deliver nothing on their own. Alerts reach one once it is a channel in a notification group that your monitors use.

<Steps>

1. Go to **Respond → Notifications**. Click a group's name to open it, or click **Add group** to make a new one.

2. Under **Notifications**, click **Add Notification Method**. Set **Notification Type** to **Discord** and choose this integration under **Integration**.

3. Click **Done editing**, then **Update Group** (**Create Group** for a new group).

</Steps>

Through the API, create the channel with [`POST /notification`](/api-reference/operations/create_notification/):

```bash
curl -X POST https://api.siteqwality.com/notification \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "notification_group_id": "<your-group-id>",
    "type": "discord",
    "details": {
      "discord_integration_id": "<discord-integration-id>"
    }
  }'
```

## Notes

- One integration per Discord channel. Create multiple integrations for multiple destinations.
- Each attempt waits up to 10 seconds and never follows a redirect. A deleted webhook (`404`), a refused one (`401`, `403`) or a redirect is recorded once as rejected and not retried. Other failures are tried up to three times in quick succession. Nothing is queued and there is no later retry, so a send that Discord rate-limits can fail.
- HTTP monitors, browser checks, TLS and domain expiry warnings, page speed alerts, alert rules and RUM issues post to Discord. Heartbeat (cron) monitors and DNS record changes do not post to Discord today. See the [coverage table](/integrations/coverage/#discord).
- Webhook URLs are secrets, since anyone with the URL can post to the channel. Rotate (delete + recreate) if leaked.
