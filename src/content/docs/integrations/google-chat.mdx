The Google Chat integration posts alerts into a space as `cardsV2` messages. It needs one thing: the space's incoming webhook URL.

## What you need

<Steps>

1. In Google Chat, open the **space** you want alerts in.

2. **Apps & integrations → Webhooks → Add webhook.**

3. Copy the URL. It looks like `https://chat.googleapis.com/v1/spaces/...`.

</Steps>

## Connect it

In the dashboard, **Integrations → Add Integrations → Google Chat**. Name it, paste the URL into **Webhook URL**, and click **Add**. Or via the API:

```bash
curl -X POST https://api.siteqwality.com/integration/google_chat \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "friendly_name": "Acme Google Chat",
    "url": "https://chat.googleapis.com/v1/spaces/..."
  }'
```

Note the request field is `url`, while the stored field is `google_chat_webhook_url`.

Both fields are required. The URL must start with `https://chat.googleapis.com/v1/spaces/`; anything else is refused with a `400` at save time. Whether the webhook still works is not checked, so a deleted webhook shows up as a failed notification.

<Aside type="note" title="The webhook URL does not read back">
A Google Chat webhook URL carries its own auth token in the query string, so `GET /integration` shows only `https://chat.googleapis.com/****`, and delivery records show only the host. Keep your own copy if you need it again. To change it, add a new integration and delete the old one.
</Aside>

## Create a channel

```bash
curl -X POST https://api.siteqwality.com/notification \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "notification_group_id": "<your-group-id>",
    "type": "google_chat",
    "details": { "google_chat_integration_id": "<google-chat-integration-id>" }
  }'
```

## Message format

Messages render as a Google Chat card with a header and a body section carrying the monitor name, URL, and status. Recovery messages use the same card shape.

## Delivery behavior

<Aside type="caution" title="A failed send is not retried later">
Google Chat rides the shared platform-webhook transport: a send is tried up to 3 times in quick succession, each with a 15 second timeout, and any non-2xx response counts as a failure. After that the alert is not retried. A send that ends with an error response shows as failed in the channel's alert history; a send that runs out of time can be lost with no record.

If Google Chat is your only alerting path for something that matters, pair it with a second channel.
</Aside>

## Limitations

Google Chat channels fire for **HTTP monitors, browser checks, domain expiry warnings, log, metric and trace alert rules, and RUM issues**. Heartbeat (cron) monitors, TLS expiry warnings, page speed alerts and DNS record changes do not reach Google Chat today: a Google Chat channel on a group used by those sources is skipped. Incidents and escalations do not use Google Chat. See the [coverage table](/incident-management/notifications/channels/#which-alerts-reach-which-channels).
