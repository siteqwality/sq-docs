The Google Chat integration posts alerts into a space as `cardsV2` messages, through the space's incoming webhook URL.

## What you need

<Steps>

1. In Google Chat, open the **space** you want alerts in.

2. **Apps & integrations → Webhooks → Add webhook.**

3. Copy the URL. It looks like `https://chat.googleapis.com/v1/spaces/...`.

</Steps>

## Connect it

In the dashboard, go to **Manage → Integrations** and click the **Google Chat** card. Name it, paste the URL into **Webhook URL**, and click **Add**.

Or through the API, with [`POST /integration/google_chat`](/api-reference/operations/add_google_chat_integration/):

```bash
curl -X POST https://api.siteqwality.com/integration/google_chat \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "friendly_name": "Acme Google Chat",
    "url": "https://chat.googleapis.com/v1/spaces/..."
  }'
```

The URL must start with `https://chat.googleapis.com/v1/spaces/`. Whether the webhook still works is not checked, so a deleted webhook shows up as a failed notification. The URL carries its own auth token and never reads back in full, so keep your own copy; to change it, add a new integration and delete the old one.

## Add it to a notification group

Right after you add the integration, the dashboard offers to do this for you: choose a group or create one, choose which monitors alert that group (the ones that already do, every monitor, or ones you pick), then send a test. If you skipped it, **Route alerts** on the integration's card opens the same step. To do it by hand:

<Steps>

1. Go to **Respond → Notifications**. Click a group's name to open it, or click **Add group** to make a new one.

2. Under **Notifications**, click **Add Notification Method**. Set **Notification Type** to **Google Chat** and choose this integration under **Integration**.

3. Click **Done editing**, then **Update Group** (**Create Group** for a new group).

</Steps>

Through the API, create the channel with [`POST /notification`](/api-reference/operations/create_notification/):

```bash
curl -X POST https://api.siteqwality.com/notification \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "notification_group_id": "<your-group-id>",
    "type": "google_chat",
    "details": { "google_chat_integration_id": "<google-chat-integration-id>" }
  }'
```

## Message format

Messages render as a Google Chat card with a header and a body section carrying the monitor name, URL, and status. Recovery messages use the same card shape.

## Delivery behavior

A failed send can get up to 3 attempts in quick succession but is never retried later, and the outcome is always recorded. If Google Chat is your only alerting path for something that matters, pair it with a second channel. See [delivery guarantees](/incident-management/notifications/channels/#delivery-guarantees-by-channel).

## Limitations

Heartbeat (cron) monitors, TLS certificate alerts, page speed alerts and DNS record changes do not reach Google Chat. See the [coverage table](/integrations/coverage/#google-chat).
