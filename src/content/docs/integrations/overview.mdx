An **integration** is a stored credential or webhook URL connecting Site Qwality to an external service. Once an integration exists, you can create [notification channels](/incident-management/notifications/channels/) that deliver to it.

The split exists because:

- One integration → many channels. One Slack workspace integration can fan into 20 different channels (`#ops`, `#deploys`, `#alerts-billing`, ...).
- Credentials are reusable. You connect Slack once via OAuth; you don't re-enter the workspace every time you want a new channel.

To let an AI assistant such as Claude or ChatGPT work with your account instead, see [Connect AI assistants (MCP)](/integrations/mcp/).

<Aside type="note" title="Not every channel works with every monitor type">
HTTP monitors, browser checks, domain expiry, alert rules and RUM issues reach every channel type. Heartbeat (cron) monitors, TLS expiry, [page-speed alerts](/uptime-monitoring/http-checks/how-to/page-speed-alerts/) and DNS record changes reach only some, and a channel of a type that a source does not support is skipped without an error. See [which alerts reach which channels](/incident-management/notifications/channels/#which-alerts-reach-which-channels).
</Aside>

## How integrations and channels relate

```
Integrations              Notification channels                Notification group
(account-level)           (group-level)                        (monitor-level)

┌──────────────────┐      ┌──────────────────┐                 ┌──────────────────┐
│ Slack workspace  │ ←──  │ Channel: #ops    │ ─┐              │                  │
│ (one OAuth)      │      └──────────────────┘  │              │  "Default group" │
│                  │      ┌──────────────────┐  ├──→ attached →│                  │
│                  │ ←──  │ Channel: #alerts │ ─┤              │                  │
└──────────────────┘      └──────────────────┘  │              │                  │
                          ┌──────────────────┐  │              │                  │
                          │ Channel: webhook │ ─┘              │                  │
                          └──────────────────┘                 └──────────────────┘
```

So the typical setup flow is:

1. Connect the **integration** (one-time OAuth or webhook URL).
2. Create a **notification channel** referencing that integration with the per-channel detail (the Slack channel name, the Telegram chat ID).
3. Add the channel to a **notification group**.
4. Attach the group to your **monitors**.
