An **integration** is a stored credential or webhook URL connecting SiteQwality to an external service. Once an integration exists, you can create [notification channels](/incident-management/notifications/channels/) that deliver to it.

The split exists because:

- One integration → many channels. One Slack workspace integration can fan into 20 different channels (`#ops`, `#deploys`, `#alerts-billing`, ...).
- Credentials are reusable. You connect Slack once via OAuth; you don't re-enter the workspace every time you want a new channel.

<Aside type="note" title="Not every channel works with every monitor type">
PagerDuty, OpsGenie, Google Chat, Mattermost, Pushover, and Pushbullet fire for **HTTP monitors, browser checks, and DNS/domain expiry**. TLS expiry and cron/heartbeat monitors support only email, SMS, and Slack today, and a channel of an unsupported type on those monitors is skipped rather than erroring.

[Page-speed alerts](/uptime-monitoring/http-checks/how-to/page-speed-alerts/) are narrower still: email, SMS, Slack, webhook, Discord, and Teams only.
</Aside>

## How integrations and channels relate

```
Integrations              Notification channels                Notification group
(account-level)           (group-level)                        (monitor-level)

┌──────────────────┐      ┌──────────────────┐                 ┌──────────────────┐
│ Slack workspace  │ ←──  │ Channel: #ops    │ ─┐              │                  │
│ (one OAuth)      │      └──────────────────┘  │              │  "Default group" │
│                  │      ┌──────────────────┐  ├──→ attached →│                  │
│                  │ ←──  │ Channel: #alerts │ ─┤              │                  │
└──────────────────┘      └──────────────────┘  │              │                  │
                          ┌──────────────────┐  │              │                  │
                          │ Channel: webhook │ ─┘              │                  │
                          └──────────────────┘                 └──────────────────┘
```

So the typical setup flow is:

1. Connect the **integration** (one-time OAuth or webhook URL).
2. Create a **notification channel** referencing that integration with the per-channel detail (the Slack channel name, the Telegram chat ID).
3. Add the channel to a **notification group**.
4. Attach the group to your **monitors**.

## Pricing

Integrations themselves are free. Delivery costs (SMS, phone calls) are extra and per-message; see [Notifications](/incident-management/notifications/overview/#pricing).
