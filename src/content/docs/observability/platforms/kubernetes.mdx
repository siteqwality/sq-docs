This guide configures logs, traces, metrics. Start with an admitted Site Qwality account and an ingest key from [API keys](https://app.siteqwality.com/account?tab=api-keys). Replace YOUR_INGEST_KEY on your server. Never use a real key in a public example.

## 1. Create the namespace and Secret

Restrict Secret access and do not commit ingest-key.txt. The daemonset reads pod logs and host metrics. Applications send OTLP to its private Service.

```bash
kubectl create namespace observability
# Save only the key in a protected local file, then remove that file after creating the Secret.
kubectl -n observability create secret generic siteqwality-ingest --from-file=key=./ingest-key.txt
```

## 2. Save values.yaml

Presets add filelog/k8s/host receivers and their RBAC. Keep resource identity from each application or Kubernetes labels rather than stamping every pod with the Collector name. Review the rendered chart for permissions, ports and resource limits.

```yaml
mode: daemonset
fullnameOverride: siteqwality-collector
service:
  enabled: true
  type: ClusterIP
resources:
  requests: {cpu: 100m, memory: 128Mi}
  limits: {cpu: 500m, memory: 512Mi}
ports:
  otlp: {enabled: false}
  otlp-http: {hostPort: null}
  jaeger-compact: {enabled: false}
  jaeger-thrift: {enabled: false}
  jaeger-grpc: {enabled: false}
  zipkin: {enabled: false}
image:
  repository: otel/opentelemetry-collector-contrib
command:
  name: otelcol-contrib
presets:
  logsCollection:
    enabled: true
  kubernetesAttributes:
    enabled: true
  hostMetrics:
    enabled: true
extraEnvs:
  - name: SQ_INGEST_KEY
    valueFrom:
      secretKeyRef: {name: siteqwality-ingest, key: key}
config:
  receivers:
    jaeger: null
    zipkin: null
  exporters:
    debug: null
    otlphttp/siteqwality:
      endpoint: https://otlp.siteqwality.com
      compression: gzip
      headers:
        Authorization: "Bearer ${env:SQ_INGEST_KEY}"
  processors:
    resource/siteqwality:
      attributes:
        - {key: deployment.environment.name, value: "production", action: upsert}
  service:
    pipelines:
      logs:
        receivers: [otlp]
        processors: [memory_limiter, resource/siteqwality, batch]
        exporters: [otlphttp/siteqwality]
      traces:
        receivers: [otlp]
        processors: [memory_limiter, resource/siteqwality, batch]
        exporters: [otlphttp/siteqwality]
      metrics:
        receivers: [otlp]
        processors: [memory_limiter, resource/siteqwality, batch]
        exporters: [otlphttp/siteqwality]
```

## 3. Install the chart and configure your application

Pin the chart and image versions after validating them in your cluster. Use OTEL_EXPORTER_OTLP_ENDPOINT=http://siteqwality-collector.observability.svc.cluster.local:4318 with http/protobuf. Keep the Service private. Test pod log parsing, namespace labels and service.name before increasing traffic.

```bash
helm repo add open-telemetry https://open-telemetry.github.io/opentelemetry-helm-charts
helm repo update
helm upgrade --install siteqwality-collector open-telemetry/opentelemetry-collector --namespace observability --values values.yaml
kubectl -n observability get pods,svc
```

## Confirm readable data

Open [Add data](https://app.siteqwality.com/add-data?platform=kubernetes), select the signal and choose **Check again**. This reads retained data permitted for your account and member. A permission error is not proof that collection failed. Open the explorer, select your service/environment and a recent window.

- Create an ingest key for this account and only the signals you send. Read-only keys cannot ingest; ingest keys cannot query. Use a separate read-only API key or your signed-in session for exploration.
- A successful OTLP HTTP response is 200 with an ExportResponse. Inspect partialSuccess for rejected records. JSON /ingest and /metrics return 200 with accepted, rejected and errors. Remote-write returns 204 on full acceptance; platform adapters use their own acknowledgement formats.
- Accepted data has been written to storage or durable spill. It can appear later during replay. Acceptance does not mean every record passed validation or that it is already searchable. Retry transient 429/5xx failures with backoff and honor Retry-After; do not blindly resend an entire partially accepted batch.
- Requests allow 4,000,000 wire bytes, up to 40,000,000 inflated bytes for logs/traces or 16,000,000 for metrics, and at most 100:1 inflation. Use gzip or supported deflate on HTTP; Prometheus uses Snappy. Split oversized requests instead of retrying unchanged.
- 401/403: check key, account, signal scope and collection access. 413: reduce batch bytes. 415: check protocol and content type. 429: check quota/cardinality/rate and wait for Retry-After. Persistent 5xx: retain your local buffer and contact support with request time, never the key.

## Production checklist

Store the key in your platform secret mechanism, rotate it when exposed and remove test keys. Set a stable service.name and deployment.environment.name; avoid user IDs or unbounded values in metric labels. Prefer a persistent queue, bounded retries and exporter failure monitoring. Review redaction and processors before increasing traffic.
