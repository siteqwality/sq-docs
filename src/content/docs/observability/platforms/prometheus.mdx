This guide covers metrics. Replace `YOUR_INGEST_KEY` with your key.

<BeforeYouStart />

## 1. Add remote_write to prometheus.yml

Merge this into your configuration, keeping existing scrape jobs. `job` becomes the fallback service name. For remote-write 2.0, change `protobuf_message` to `io.prometheus.write.v2.Request`, but only on a Prometheus version that supports it. Do not send text exposition to this route.

```yaml
global:
  external_labels:
    env: "production"
scrape_configs:
  - job_name: "my-service"
    static_configs:
      - targets: ["127.0.0.1:9090"]
remote_write:
  - url: https://otlp.siteqwality.com/api/v1/write
    protobuf_message: prometheus.WriteRequest
    authorization:
      credentials: "YOUR_INGEST_KEY"
    send_exemplars: true
    queue_config:
      max_samples_per_send: 1000
      retry_on_http_429: true
```

## 2. Validate and reload

In production, keep credentials in a protected `credentials_file`. Enable retries for 429 responses, monitor queue age and keep label cardinality bounded.

```bash
promtool check config prometheus.yml
# Reload using your deployment process, then check remote-write pending and failed samples.
```

## See your data

Open [Metrics](https://app.siteqwality.com/metrics). New data usually shows up within a minute. Nothing arriving? See [failure handling](/observability/ingest/#failure-handling).

## Production checklist

Store the key in your platform secret mechanism, rotate it when exposed and remove test keys. Keep service and environment names stable; avoid user IDs or unbounded values in metric labels. Review [redaction and processors](/observability/pipelines/) before increasing traffic.
