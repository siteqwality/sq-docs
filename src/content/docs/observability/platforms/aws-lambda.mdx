## 1. Choose a Lambda instrumentation layer

Attach the published layer ARN from the official Lambda instructions for your runtime, region and architecture; never reuse an ARN from another region or architecture. For Java or .NET, use their runtime-specific Lambda instrumentation.

```text
Runtime: Node.js or Python
Layer: official OpenTelemetry Lambda layer for your runtime, region and CPU architecture
Node wrapper: AWS_LAMBDA_EXEC_WRAPPER=/opt/otel-handler
Python wrapper: AWS_LAMBDA_EXEC_WRAPPER=/opt/otel-instrument
```

## 2. Set server environment variables

Set these on the running service. Keep the key out of source control, client bundles and build logs.

```bash
export OTEL_SERVICE_NAME='my-service'
export OTEL_RESOURCE_ATTRIBUTES='deployment.environment.name=production'
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_LOGS_ENDPOINT='https://otlp.siteqwality.com/v1/logs'
export OTEL_EXPORTER_OTLP_LOGS_HEADERS='Authorization=YOUR_INGEST_KEY'
export OTEL_EXPORTER_OTLP_TRACES_ENDPOINT='https://otlp.siteqwality.com/v1/traces'
export OTEL_EXPORTER_OTLP_TRACES_HEADERS='Authorization=YOUR_INGEST_KEY'
export OTEL_EXPORTER_OTLP_METRICS_ENDPOINT='https://otlp.siteqwality.com/v1/metrics'
export OTEL_EXPORTER_OTLP_METRICS_HEADERS='Authorization=YOUR_INGEST_KEY'
export OTEL_LOGS_EXPORTER=otlp
export OTEL_TRACES_EXPORTER=otlp
export OTEL_METRICS_EXPORTER=otlp
```

## 3. Invoke and check the exporter

Add the variables through your infrastructure secret mechanism without replacing the function's whole environment, then invoke it with a test event it accepts. Export during the invocation or use the Collector extension; a background timer may be frozen after return. CloudWatch logs arrive only if a logging bridge, extension or Firehose forwards them.

```bash
aws lambda invoke --function-name YOUR_FUNCTION --payload fileb://event.json response.json
```

## See your data

Open [Logs](https://app.siteqwality.com/logs), [Traces](https://app.siteqwality.com/traces) or [Metrics](https://app.siteqwality.com/metrics). New data usually shows up within a minute. Nothing arriving? See [failure handling](/observability/ingest/#failure-handling).

## Production checklist

Store the key in your platform secret mechanism, rotate it when exposed and remove test keys. Set a stable service.name and deployment.environment.name; avoid user IDs or unbounded values in metric labels. Prefer a persistent queue, bounded retries and exporter failure monitoring. Review redaction and processors before increasing traffic.
