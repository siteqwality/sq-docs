Syslog over TLS (port 6514) is not available yet, so this configuration does not connect. Send logs over OTLP/HTTP instead, for example with the [OpenTelemetry Collector](/observability/platforms/collector/), [Fluent Bit](/observability/platforms/fluent-bit/) or [Vector](/observability/platforms/vector/). There is no public UDP syslog port.

This guide covers logs. Replace `YOUR_INGEST_KEY` with your key.

<BeforeYouStart />

## 1. Configure rsyslog TLS forwarding

This needs the rsyslog TLS module and a writable `workDirectory` for the queue. Replace both hostname occurrences and the PEN. The RFC 5424 structured-data element supplies the key, which Site Qwality strips before storage; include it on the first record of every new connection. Do not disable certificate verification.

```text
global(workDirectory="/var/spool/rsyslog" DefaultNetstreamDriver="gtls" DefaultNetstreamDriverCAFile="/etc/ssl/certs/ca-certificates.crt")
module(load="imfile")
template(name="sq5424" type="string" string="<%PRI%>1 %TIMESTAMP:::date-rfc3339% %HOSTNAME% app %PROCID% - [sq@YOUR_ASSIGNED_PEN key=\"YOUR_INGEST_KEY\"] %msg%\n")
input(type="imfile" File="/var/log/my-app/app.log" Tag="app" ruleset="siteqwality")
ruleset(name="siteqwality") {
  action(type="omfwd" target="YOUR_ENABLED_SYSLOG_HOST" port="6514" protocol="tcp"
    StreamDriver="gtls" StreamDriverMode="1" StreamDriverAuthMode="x509/name"
    StreamDriverPermittedPeers="YOUR_ENABLED_SYSLOG_HOST"
    TCP_Framing="octet-counted" template="sq5424"
    queue.type="LinkedList" queue.filename="siteqwality" queue.saveOnShutdown="on" action.resumeRetryCount="-1")
}
```

## 2. Validate the configuration

Check the configuration with this command, then restart rsyslog with your service manager and append a line to the configured file. TLS/TCP syslog has no per-record durable application acknowledgment, so watch your local queue.

```bash
rsyslogd -N1
```

## Production checklist

Store the key in your platform secret mechanism, rotate it when exposed and remove test keys. Keep service and environment names stable. Prefer a persistent queue, bounded retries and delivery failure monitoring. Review [redaction and processors](/observability/pipelines/) before increasing traffic.
