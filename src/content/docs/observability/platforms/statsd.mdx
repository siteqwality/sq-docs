## 1. Save collector.yaml

Use the contrib distribution. StatsD listens only on your local Collector at UDP 8125; Site Qwality has no public StatsD UDP port.

```yaml
receivers:
  otlp:
    protocols:
      http:
        endpoint: 127.0.0.1:4318
  statsd:
    endpoint: 127.0.0.1:8125
    aggregation_interval: 10s
processors:
  memory_limiter:
    check_interval: 1s
    limit_mib: 256
    spike_limit_mib: 64
  resource:
    attributes:
      - {key: service.name, value: "my-service", action: upsert}
      - {key: deployment.environment.name, value: "production", action: upsert}
  batch:
    send_batch_size: 256
    send_batch_max_size: 512
    timeout: 1s
exporters:
  otlphttp/siteqwality:
    endpoint: https://otlp.siteqwality.com
    headers:
      Authorization: "Bearer YOUR_INGEST_KEY"
    compression: gzip
    sending_queue: {enabled: true, queue_size: 1000}
    retry_on_failure: {enabled: true, initial_interval: 1s, max_interval: 30s, max_elapsed_time: 300s}
service:
  pipelines:
    metrics:
      receivers: [statsd]
      processors: [memory_limiter, resource, batch]
      exporters: [otlphttp/siteqwality]
```

## 2. Start the Collector

A memory queue survives transient failures, not process loss; for host restart durability, use the `file_storage` extension and a persistent sending queue. Keep batches within the [receiver byte limits](/observability/ingest/#content-types-and-compression).

```bash
otelcol-contrib --config=collector.yaml
```

## 3. Send a local StatsD counter

Wait for the aggregation interval, then inspect Metrics. StatsD datagrams have no durable sender acknowledgment.

```bash
printf 'example.requests:1|c
' | nc -u -w 1 127.0.0.1 8125
```

## See your data

Open [Logs](https://app.siteqwality.com/logs), [Traces](https://app.siteqwality.com/traces) or [Metrics](https://app.siteqwality.com/metrics). New data usually shows up within a minute. Nothing arriving? See [failure handling](/observability/ingest/#failure-handling).

## Production checklist

Store the key in your platform secret mechanism, rotate it when exposed and remove test keys. Set a stable service.name and deployment.environment.name; avoid user IDs or unbounded values in metric labels. Prefer a persistent queue, bounded retries and exporter failure monitoring. Review redaction and processors before increasing traffic.
