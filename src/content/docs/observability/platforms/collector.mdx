## 1. Save collector.yaml

Install the Collector contrib distribution. This example binds local OTLP/HTTP only. Bind to a private interface with access controls if other hosts must send to it.

<Snippet code={config} lang="yaml" title="collector.yaml" />

## 2. Start the Collector

A memory queue survives transient failures, not process loss; for host restart durability, use the `file_storage` extension and a persistent sending queue. Keep batches within the [receiver byte limits](/observability/ingest/#content-types-and-compression).

<Snippet code={run} lang="bash" />

## 3. Point your application at the local Collector

The Collector holds the ingest key, so the application needs none. Enable the SDK exporters you use. The Collector appends `/v1/logs`, `/v1/traces` and `/v1/metrics` to its cloud endpoint.

```bash
export OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
export OTEL_EXPORTER_OTLP_ENDPOINT=http://127.0.0.1:4318
```

## See your data

Open [Logs](https://app.siteqwality.com/logs), [Traces](https://app.siteqwality.com/traces) or [Metrics](https://app.siteqwality.com/metrics). New data usually shows up within a minute. Nothing arriving? See [failure handling](/observability/ingest/#failure-handling).

## Production checklist

Store the key in your platform secret mechanism, rotate it when exposed and remove test keys. Set a stable service.name and deployment.environment.name; avoid user IDs or unbounded values in metric labels. Prefer a persistent queue, bounded retries and exporter failure monitoring. Review redaction and processors before increasing traffic.
