## 1. Store the Worker secret

Enter the ingest key at the prompt. This example sends logs to the JSON adapter without an SDK.

```bash
npx wrangler secret put SQ_INGEST_KEY
```

## 2. Send a bounded server-side log

`waitUntil` extends the request lifetime but is not a durable queue; in production, batch and use a durable queue with bounded retries. Avoid logging full URLs, authorization headers or personal data. To export platform logs instead, use [Cloudflare Logpush](/observability/platforms/cloudflare-logpush/).

```javascript
export default {
  async fetch(request, env, ctx) {
    ctx.waitUntil((async () => {
      const response = await fetch("https://otlp.siteqwality.com/ingest", {
        method: "POST",
        headers: {"Content-Type": "application/json", "Authorization": "Bearer " + env.SQ_INGEST_KEY},
        body: JSON.stringify({message: "Worker request", level: "info", service: "my-service", env: "production"})
      });
      if (!response.ok) throw new Error("Telemetry send failed with status " + response.status);
      const result = await response.json();
      if (result.rejected) throw new Error("Telemetry record rejected");
    })());
    return new Response("ok");
  }
};
```

## 3. Deploy the Worker

Make one request and inspect Logs. This does not automatically emit traces or metrics.

```bash
npx wrangler deploy
```

## See your data

Open [Logs](https://app.siteqwality.com/logs). New data usually shows up within a minute. Nothing arriving? See [failure handling](/observability/ingest/#failure-handling).

## Production checklist

Store the key in your platform secret mechanism, rotate it when exposed and remove test keys. Keep service and environment names stable. Prefer a persistent queue, bounded retries and delivery failure monitoring. Review [redaction and processors](/observability/pipelines/) before increasing traffic.
