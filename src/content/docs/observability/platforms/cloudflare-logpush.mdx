## 1. Create a Logpush HTTP destination

Create the Logpush job for your account with this body. The `http_requests` dataset also works, with its own fields. Cloudflare reads the `header_*` parameters in `destination_conf` as request headers, so that URL contains a credential and must be protected.

```json
{
  "name": "siteqwality",
  "dataset": "workers_trace_events",
  "enabled": true,
  "destination_conf": "https://otlp.siteqwality.com/v1/cloudflare?header_Authorization=Bearer%20YOUR_INGEST_KEY",
  "max_upload_records": 1000
}
```

## 2. Verify the dataset and validation

Workers logs map ScriptName and EventTimestamp; HTTP requests map RayID and EdgeStartTimestamp. The receiver requires gzip bounds and accepts only the implemented datasets. Cloudflare minimum batch settings can exceed the receiver wire limit for large records; use a splitting bridge when batches cannot stay below 4,000,000 compressed bytes and 40,000,000 inflated bytes.

```text
Allow the ownership validation request containing the content=test validation object. Enable the job, generate a Worker request and inspect Logpush delivery errors and Logs.
```

## See your data

Open [Logs](https://app.siteqwality.com/logs). New data usually shows up within a minute. Nothing arriving? See [failure handling](/observability/ingest/#failure-handling).

## Production checklist

Treat the URL that carries the key as a secret, rotate the key when exposed and remove test keys. Keep service and environment names stable and monitor delivery errors. Review [redaction and processors](/observability/pipelines/) before increasing traffic.
