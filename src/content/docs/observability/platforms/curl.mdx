This guide configures logs, traces, metrics. Start with an admitted Site Qwality account and an ingest key from [API keys](https://app.siteqwality.com/account?tab=api-keys). Replace YOUR_INGEST_KEY on your server. Never use a real key in a public example.

## 1. Send an OTLP logs sample

Run in a terminal with curl and a POSIX shell. Each run generates a current timestamp. The trace sample uses fixed demonstration IDs; use unique IDs for real requests.

```bash
timestamp="$(date +%s)000000000"
curl --fail-with-body -X POST 'https://otlp.siteqwality.com/v1/logs' \
  -H 'Authorization: Bearer YOUR_INGEST_KEY' \
  -H 'Content-Type: application/json' \
  --data-binary '{"resourceLogs":[{"resource":{"attributes":[{"key":"service.name","value":{"stringValue":"my-service"}},{"key":"deployment.environment.name","value":{"stringValue":"production"}}]},"scopeLogs":[{"logRecords":[{"timeUnixNano":"'"$timestamp"'","severityNumber":9,"severityText":"INFO","body":{"stringValue":"Hello from my service"}}]}]}]}'
```

## 2. Send an OTLP traces sample

Run in a terminal with curl and a POSIX shell. Each run generates a current timestamp. The trace sample uses fixed demonstration IDs; use unique IDs for real requests.

```bash
timestamp="$(date +%s)000000000"
start_timestamp="$(($(date +%s) - 1))000000000"
curl --fail-with-body -X POST 'https://otlp.siteqwality.com/v1/traces' \
  -H 'Authorization: Bearer YOUR_INGEST_KEY' \
  -H 'Content-Type: application/json' \
  --data-binary '{"resourceSpans":[{"resource":{"attributes":[{"key":"service.name","value":{"stringValue":"my-service"}},{"key":"deployment.environment.name","value":{"stringValue":"production"}}]},"scopeSpans":[{"spans":[{"traceId":"4bf92f3577b34da6a3ce929d0e0e4736","spanId":"00f067aa0ba902b7","name":"example.request","kind":2,"startTimeUnixNano":"'"$start_timestamp"'","endTimeUnixNano":"'"$timestamp"'","status":{"code":1}}]}]}]}'
```

Run in a terminal with curl and a POSIX shell. Each run generates a current timestamp. The trace sample uses fixed demonstration IDs; use unique IDs for real requests.

```bash
timestamp="$(date +%s)000000000"
curl --fail-with-body -X POST 'https://otlp.siteqwality.com/v1/metrics' \
  -H 'Authorization: Bearer YOUR_INGEST_KEY' \
  -H 'Content-Type: application/json' \
  --data-binary '{"resourceMetrics":[{"resource":{"attributes":[{"key":"service.name","value":{"stringValue":"my-service"}},{"key":"deployment.environment.name","value":{"stringValue":"production"}}]},"scopeMetrics":[{"metrics":[{"name":"example.temperature","unit":"Cel","gauge":{"dataPoints":[{"timeUnixNano":"'"$timestamp"'","asDouble":21.5}]}}]}]}]}'
```

## Confirm readable data

Open [Add data](https://app.siteqwality.com/add-data?platform=curl), select the signal and choose **Check again**. This reads retained data permitted for your account and member. A permission error is not proof that collection failed. Open the explorer, select your service/environment and a recent window.

- Create an ingest key for this account and only the signals you send. Read-only keys cannot ingest; ingest keys cannot query. Use a separate read-only API key or your signed-in session for exploration.
- A successful OTLP HTTP response is 200 with an ExportResponse. Inspect partialSuccess for rejected records. JSON /ingest and /metrics return 200 with accepted, rejected and errors. Remote-write returns 204 on full acceptance; platform adapters use their own acknowledgement formats.
- Accepted data has been written to storage or durable spill. It can appear later during replay. Acceptance does not mean every record passed validation or that it is already searchable. Retry transient 429/5xx failures with backoff and honor Retry-After; do not blindly resend an entire partially accepted batch.
- Requests allow 4,000,000 wire bytes, up to 40,000,000 inflated bytes for logs/traces or 16,000,000 for metrics, and at most 100:1 inflation. Use gzip or supported deflate on HTTP; Prometheus uses Snappy. Split oversized requests instead of retrying unchanged.
- 401/403: check key, account, signal scope and collection access. 413: reduce batch bytes. 415: check protocol and content type. 429: check quota/cardinality/rate and wait for Retry-After. Persistent 5xx: retain your local buffer and contact support with request time, never the key.

## Production checklist

Store the key in your platform secret mechanism, rotate it when exposed and remove test keys. Set a stable service.name and deployment.environment.name; avoid user IDs or unbounded values in metric labels. Prefer a persistent queue, bounded retries and exporter failure monitoring. Review redaction and processors before increasing traffic.
