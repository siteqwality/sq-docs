Errors lists browser issues and backend exception groups together, labeled by source. Filter by source, service, environment, time and status. Backend groups come from supported exception events, stack traces and log patterns in received telemetry. An error-level line without a parseable exception is still searchable in Logs and need not create a stack-based issue.

Open an issue to inspect its fingerprint, title, culprit, event samples, affected versions and activity. Grouping normalizes supported language stacks; unrelated exception families should not be merged solely because their messages match. Samples can be absent after retention or under your access restrictions, so a count does not mean every original stack is still available.

Use the issue workflow to assign, resolve, ignore or reopen issues. Before a backend merge, check the selected service, environment and fingerprint: a merge changes future grouping and workflow. Browser issue actions follow the RUM workflow and access policy. Readable browser stacks need uploaded [source maps](/observability/rum/how-to/source-maps/), and replay needs a [recording rule](/observability/rum/how-to/session-filters/) and replay access.

| API path | Purpose |
|---|---|
| `GET /errors` | Unified scoped issue list. |
| `GET /errors/backend/{service}/{fingerprint}` | Backend issue detail. |
| `GET /errors/backend/{service}/{fingerprint}/events` | Bounded event samples. |
| `PATCH /errors/backend/{service}/{fingerprint}` | Supported lifecycle/ownership changes. |
| `POST /errors/backend/bulk` | Explicit bulk action. |
| `POST /errors/backend/merge` | Merge selected backend identities. |

Use the API schema for each mutation body and URL-encode service and fingerprint values. Pipeline redaction runs before exception extraction; test stacks with representative safe samples in [Processing pipelines](/observability/pipelines/).

This workflow does not page, open an incident or post a status update. To be notified about exception-related changes, create a telemetry [alert rule](/observability/alerts/).
