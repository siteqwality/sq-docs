A **saved view** is a named, reusable filter set on the Logs Explorer. Use them for:

- "All errors in billing prod" (the search the on-call opens during pages).
- "Slow queries (>1s) on the search service."
- "Logs with `metadata.user_id = X`" (for one-off customer support investigations).

## Create

<Tabs syncKey="interface">
<TabItem label="Dashboard">

On the **Logs** page, apply your filters. Click **Save view**. Name it. Toggle **Shared** if it should be visible to teammates. Save.

</TabItem>
<TabItem label="API">

```bash
curl -X POST https://api.siteqwality.com/log_saved_views \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Billing errors (prod)",
    "description": "All error-level logs from billing-api in prod, last 24h",
    "is_shared": true,
    "filters": {
      "source": "billing-api",
      "env": "prod",
      "level": "error"
    }
  }'
```

The `filters` object is stored as given. The dashboard stores its own filter state there, so a view saved from the API may not load the filters you expect: save one from the dashboard and read it back to see the shape.

<Aside type="caution" title="API-created views cannot be changed">
Only the user who created a view can update or delete it. A view created with an API key has no creating user, so nobody can update or delete it afterwards, from the API or the dashboard. Create views you may want to change from the dashboard.
</Aside>

</TabItem>
</Tabs>

## Personal vs shared

- **Personal** views are visible only to the user who created them. Use for ad-hoc, "remember this for me" filters.
- **Shared** views appear in everyone's sidebar. Use for runbook-style queries the whole team should reach for.

Only the user who created a view can update or delete it, even when it is shared. Update with `PUT /log_saved_views/{view_id}` while signed in as that user.

## Naming conventions

For shared views, prefix with a category for sortability:

- `[Errors] Billing (prod)`
- `[Errors] Auth (prod)`
- `[Slow] Search > 1s`
- `[Audit] Admin actions`
- `[Customer] usr_<known-customer>`

## Maintenance

- **Delete unused views.** They accumulate, so a quarterly cleanup is healthy.
- **Mind the time range.** A view saved from the dashboard stores the exact start and end time that were selected, not a relative range like "last 1h". After loading an older view, set the time range you want.
- **Don't bake in user IDs.** For one-off customer investigations, run the filter in Explorer; don't save a permanent view per customer.

<Aside type="tip">
A common pattern: add a saved view for every paging notification. The pager link drops the on-call into a pre-filtered view of the relevant logs, no clicking around at 3am.
</Aside>
