## Ingest

Send OTLP to `/v1/logs` or custom JSON/NDJSON/text to `/ingest` at `https://otlp.siteqwality.com`. See [ingest routes](/observability/ingest/) and [Fluent Bit](/observability/platforms/fluent-bit/), [Vector](/observability/platforms/vector/) or [Collector](/observability/platforms/collector/) for concrete configs.

Common body aliases include `message`, `msg`, `body` and wrapper `log`; severity accepts supported textual/numeric conventions. Service/environment/resource fields have explicit identity precedence. Structured custom attributes are retained and typed subject to truncation limits; they are not restricted to an old metadata-only field list. Logs can carry valid `trace_id` and `span_id` to open recorded trace context. Invalid IDs do not create a trace link.

## Explore and query

| Path | Method | Purpose |
|---|---|---|
| `/logs/v2/search` | POST / GET | Cursor-paged event search. |
| `/logs/v2/count` | POST / GET | Matching count. |
| `/logs/v2/histogram` | POST / GET | Time buckets. |
| `/logs/v2/facets` | POST / GET | Scoped field values. |
| `/logs/v2/fields` | GET | Field catalog. |
| `/logs/v2/patterns` | GET | Bounded grouped message templates. |
| `/logs/v2/tail` | GET | Cursor-based live polling. |
| `/logs/v2/analytics` | POST | Count, numeric/distribution operations and groups. |
| `/logs/v2/events/{event_id}` | GET | Event detail. |
| `/logs/v2/events/{event_id}/context` | GET | Neighboring retained events. |
| `/logs/v2/insights` | GET | Bounded exploratory insights. |

These paths are relative to `https://api.siteqwality.com` and require read access. POST search wraps the versioned event query in `query` and supports `limit` and `cursor`; [query reference](/observability/query/) has a complete curl request. Use the same pinned range and query for cursor paging.

Live tail polls at its configured interval and keeps a bounded client buffer. It can pause or fall behind; inspect dropped/backlog indicators. It is not an SSE stream or a guarantee of subsecond end-to-end ingest latency. Analytics and patterns describe the selected window and restrictions. Insights are exploratory output, not delivered alerts.

The UI exposes typed field predicates, event details, context, analysis and saved views. Structured fields and numeric fields remain distinct. A `body_clipped` list item is a preview; inspect detail before assuming the full body is visible. Retention can clamp a query and partial results require attention.

## Saved views, processing and exports

Saved views use `/telemetry/views`, scoped to page `logs`, with a versioned query and display settings. Shared views preserve access restrictions; sharing does not grant more data. Use the UI for ownership and revision behavior.

Use [Processing pipelines](/observability/pipelines/) for new parsing/redaction rules. Legacy `/log_parsers` is not the pipeline API, and parsers created there are not converted to pipelines automatically. Use [bounded exports](/observability/privacy/#exports) from the explorer; inline download allows 10,000 rows and 4 MiB compressed.

Logs have their own [decimal-GB allowance and retention](/observability/billing/). A metric derived from a log has metric-series semantics as well; it is not free unlimited cardinality.
