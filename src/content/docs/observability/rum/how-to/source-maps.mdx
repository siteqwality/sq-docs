---
title: Upload source maps
description: Match production JavaScript errors to original source with Debug IDs and private source maps.
---

Source maps translate generated JavaScript locations into original files, functions and lines. Debug IDs identify the exact emitted bundle independently of its URL or release name. Source maps remain included on every plan.

## SDK compatibility

Debug ID capture is supported by SDK **2.1.0**. Its npm rollout tag is `next`; the `latest` tag still selects SDK 1. Follow the [SDK 2 rollout and installation guide](/sdk/v2/) before changing your browser SDK. CLI or bundler installation alone does not upgrade the browser SDK or enable Debug ID capture.

For errors without a Debug ID, matching by the SDK's configured release and generated bundle filename remains supported. Keep the SDK release value and uploaded release version aligned.

## Build and inject

Install the published CLI with Node.js 22 or newer:

```sh
npm install --save-dev @siteqwality/cli@0.1.0
npm run build
npx siteqwality sourcemaps inject ./dist
```

Enable external or hidden version 3 source maps in your build. Injection adds a deterministic UUIDv8 to the bundle's runtime registration and map. It preserves mapped positions and source content. The browser SDK captures the ID with errors. Deploy the exact injected JavaScript. Run signing and integrity generation after injection, and do not minify or rewrite the output afterward.

Inline and indexed maps are unsupported. Injection rejects unsafe paths, symlinks, conflicting IDs and changed previously injected files. Rebuild from clean output when a pair changes.

## Upload from CI

Keep your API key in the CI secret store. It must have `write:rum` for uploads and release changes, plus `read:rum` to list releases. Never embed it in the browser bundle.

```sh
export SITEQWALITY_APP_ID='your-application-uuid'
export SITEQWALITY_API_KEY='your-ci-secret'
export SITEQWALITY_RELEASE='web-2026.10.04'
npx siteqwality sourcemaps upload ./dist --delete-after
# Deploy the exact injected files, then record a successful deployment:
npx siteqwality releases deploy "$SITEQWALITY_RELEASE" --env production
npx siteqwality releases list
```

Upload creates the release if needed, presigns batches of up to 50 maps, uploads gzip bytes, then confirms each batch. Each map is limited to 32 MiB both compressed and inflated. `--delete-after` removes selected local maps only after all uploads are confirmed. A failure exits nonzero and must prevent deployment. Confirmation verifies storage metadata; verify a real error's original location separately.

Without a release, uploads use the reserved `__debug_id__` release and require Debug IDs. A deployment record does not deploy your site or change the SDK's release setting.

## Bundler adapters

Install the published bundler adapters with Node.js 22 or newer:

```sh
npm install --save-dev @siteqwality/unplugin@0.1.0
```

Vite example:

```js
import { defineConfig } from 'vite';
import siteqwality from '@siteqwality/unplugin/vite';
export default defineConfig({
  plugins: [siteqwality({ release: 'web-v1', deleteAfter: true })],
});
```

Equivalent adapters are exported from `@siteqwality/unplugin/rollup`, `/webpack` and `/esbuild`. They use the same CI environment variables. Place the adapter after JavaScript and map transforms. Use `upload: false` for local injection without upload; it cannot be combined with `deleteAfter: true`.

Rollup needs external `sourcemap: true`. webpack supports `source-map`, `hidden-source-map` and `nosources-source-map`. esbuild needs an `outdir` or `outfile` and external maps. Vite enables external production maps and does not upload from the development server.

The adapter defines `__SQ_RELEASE__`; explicitly pass that value to the SDK's `release` option. TypeScript applications can declare `declare const __SQ_RELEASE__: string`. Keep credentials out of compile-time defines. Bundle filenames retain their pre-injection hashes, so generate SRI from final bytes.

## Direct API uploads

API requests use `Authorization: Bearer <API_KEY>` and `Content-Type: application/json`. Successful responses wrap results in `data`. All routes are scoped to your application under `/rum/{app_id}`.

1. Create or reuse a release with `POST /releases` and `{"version":"web-v1"}`.
2. Call `POST /releases/web-v1/sourcemaps` with the batch shown below.
3. PUT the exact bytes to each returned `data.files[].upload_url` within its 300-second lifetime, using every returned header and the declared byte length. Do not send API authorization to storage.
4. Call `POST /sourcemaps/confirm` with `{ "ids": ["returned-upload-uuid"] }`.

```json
{
  "files": [{
    "filename": "assets/main.js.map",
    "debug_id": "bf1f8d8f-6ab0-88f3-b53b-f8085758df31",
    "size_bytes": 1234,
    "content_type": "application/json",
    "content_encoding": "gzip"
  }]
}
```

`size_bytes` is the exact uploaded size, including gzip encoding. Use a byte buffer or Blob so the HTTP client supplies Content-Length, or set it when streaming from a CLI. URL-encode release versions in path segments. Filenames identify source maps and may include a relative directory, such as `assets/main.js.map`. Pending uploads are excluded from symbolication until confirmation succeeds. The original single-map `POST /releases/{version}/sourcemaps` endpoint remains compatible with existing release/filename integrations.

## Late maps and troubleshooting

The occurrence API performs symbolication on read. A map uploaded after an error can resolve its stored generated coordinates without changing issue grouping. Debug ID lookup takes priority; release and bundle filename provide a fallback. Missing or invalid maps leave generated frames readable. Failed lookups are not cached, while successful event symbolication can be cached for 24 hours.

Check that the deployed bundle is the injected file, the SDK captured its Debug ID, the uploaded map has the same ID, and the upload was confirmed. If source context is absent, ensure the map includes `sourcesContent`. Source-map columns are zero-based internally; the API presents source locations with one-based line and column values.

Keep maps out of public hosting. Hidden maps avoid a browser source-map URL but still need exclusion from deployed assets or deletion after confirmed upload. Maps can contain your complete source code. MCP and Connected App responses omit source context and other sensitive occurrence fields.
