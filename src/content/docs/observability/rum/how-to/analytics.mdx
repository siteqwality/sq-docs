RUM analytics connects aggregate traffic and performance results to the sessions behind them. The default range is 30 days; a request can cover at most 90 days.

## Overview and traffic

Overview reports sessions, views, visitors, errors, bounce rate, median active time and Web Vitals. Compare with the previous period to use an equal-length, non-overlapping window. Desktop and mobile selectors combine with the other filters; mobile includes tablets.

Bounce rate is the fraction of matching sessions with one matching view and known active time below 10 seconds. Missing active-time measurements are not treated as zero. Visitors use anonymous ID, then a retained user ID, then session ID when neither identity is available. User and anonymous-ID filters follow the Sessions 30-day identity window, including when opening sessions from an analytics row.

Traffic charts support sessions, views, errors and the percentage of sessions with errors. Daily buckets respect the selected time zone. Missing buckets are absent from the API response.

## Pages and attribution

Group Pages by normalized route or raw URL path. Each row includes views, sessions, error rate and p75 LCP, INP, CLS and loading times. Initial page loads and route changes have separate loading-time columns. A null percentile means no valid sample exists, not zero milliseconds.

For LCP, INP or CLS, open attribution to inspect the elements associated with poor samples. Each row includes its share of poor samples and example sessions. Script rows report recorded Long Animation Frame script durations; resource rows report resource timing. An `approximate` flag identifies results based on representative SDK resource aggregates.

## Dimensions and frustration

Panels group matching activity by route, entry page, exit page, referrer, channel, UTM campaign, country, device, browser, operating system and release. Frustration elements show action targets with rage, dead and error clicks. Empty dimension values represent unknown values.

Follow a result into Sessions with the returned `session_query`, and keep its opaque `cohort` parameter when changing sort or pagination. It preserves the row's membership, including per-view filters, so the Sessions total matches the row for unchanged data. Without it, a Sessions search can include a session whose page view preceded the range but whose later activity falls in it; Overview requires a view within the range.

## API examples

```http
GET /rum/{app_id}/overview?from=2026-10-01&to=2026-10-03&compare=previous&device_class=mobile
GET /rum/{app_id}/timeseries?metric=views&interval=1h&tz=Europe/Rome
GET /rum/{app_id}/panels/frustration_elements?limit=20
GET /rum/{app_id}/pages?group_by=route&f=browser:eq:Firefox
GET /rum/{app_id}/pages/attribution?metric=lcp&route=%2Fcheckout
```

Use repeated `f` parameters for multiple filters. If a query runs past its time budget, narrow the range or filters before retrying. See the [RUM API reference](/observability/rum/reference/) and [saved views and comments](/observability/rum/how-to/collaboration/).
