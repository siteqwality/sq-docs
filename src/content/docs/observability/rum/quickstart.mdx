By the end of this guide you'll have the RUM SDK installed in a web app, a session showing up in the dashboard, and you'll know how to identify users and track custom actions.

## 1. Create a RUM application

<Tabs syncKey="interface">
<TabItem label="Dashboard">

<Steps>

1. **RUM → Applications → New application.**

2. **Name:** `Web app` (or whatever's descriptive). **Domain:** `https://app.example.com`. Save.

3. The next screen shows the **`application_id`** and **`client_token`**. Copy both. The `client_token` is public and ships in your bundle; the `application_id` is also public.

</Steps>

</TabItem>
<TabItem label="API">

```bash
curl -X POST https://api.siteqwality.com/rum \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Web app",
    "domain": "https://app.example.com"
  }'
```

The response includes `id` (the `application_id`) and `client_token`.

</TabItem>
</Tabs>

## 2. Install the SDK

For an application enabled for the SDK 2 rollout, follow [SDK 2 installation](/sdk/v2/#install) and update [CSP and endpoints](/observability/rum/how-to/csp/) first. The examples below deliberately install **SDK 1.x** while that rollout is pending; do not combine an unpinned npm install with this legacy reference.

<Tabs syncKey="install">
<TabItem label="NPM">

```bash
npm install @siteqwality/rum@1.0.7
```

At the 2026-10-04 checkpoint, npm has 1.0.7; CDN `/rum/v1/` is reported to serve 1.1. SDK 1.1 options such as `ignoreErrors`, `beforeSend` and `recorderUrl` are not available in the 1.0.7 npm package. For SDK2, check the [release channels](/sdk/v2/#install) before choosing an install path.

```javascript
// In your app's entry point, before any user code
import { SiteQwalityRUM } from '@siteqwality/rum';

SiteQwalityRUM.init({
  applicationId: 'abc123',
  clientToken: 'pub_def456',
  // version: '1.4.2', // your release; enables source-mapped stack traces
});
```

For React/Vue/Svelte, init in the entry file (`main.ts`/`main.js`) before mounting the root component.

</TabItem>
<TabItem label="CDN">

Paste this into your page's `<head>`, as high as you can:

```html
<script>
  (function(w,d,s,u){var r=w.SiteQwalityRUM=w.SiteQwalityRUM||{_q:[]};if(r._q&&!r._h){
  ['init','setUser','setGlobalAttribute','removeGlobalAttribute','addError','addAction'].forEach(function(m){
    r[m]=function(){r._q.push([m,arguments])}});
  r._h=function(e){r._q.push(['_e',[e]])};w.addEventListener('error',r._h);
  w.addEventListener('unhandledrejection',r._h);
  var e=d.createElement(s);e.async=1;e.src=u;(d.head||d.documentElement).appendChild(e)}
  })(window,document,'script','https://cdn.siteqwality.com/rum/v1/sdk.min.js');

  SiteQwalityRUM.init({
    applicationId: 'abc123',
    clientToken: 'pub_def456',
    // version: '1.4.2', // your release; enables source-mapped stack traces
  });
</script>
```

The snippet loads the SDK asynchronously, so it never blocks rendering. Until the SDK arrives it queues your `init`, `setUser`, `setGlobalAttribute`, `removeGlobalAttribute`, `addError` and `addAction` calls and captures any error the page throws. When the SDK loads it runs `init` first, then the rest in order, and reports the early errors with their original times. It is a classic script and needs no `type="module"`.

</TabItem>
</Tabs>

On CDN SDK 1.1, `init()` is fire-and-forget. Collection starts synchronously inside the call, so there is nothing to wait for. It returns a Promise that settles once the remote config is applied (or fails to load); you never need to `await` it, and awaiting it only delays your app.

With the npm package, calls made before `init()` (`setUser`, `addError` and the rest) are ignored, so call `init()` first. The CDN snippet queues them instead.

## 3. Open the app

Load your app in a fresh browser. The SDK starts a session immediately and posts the first batch within ~10 seconds.

## 4. See it in the dashboard

<Tabs syncKey="interface">
<TabItem label="Dashboard">

In **RUM → Sessions**, your session appears at the top with its start time, entry page, duration and error count. If you came from the setup wizard, its verify step turns green within about 10 seconds of the first page view.

</TabItem>
<TabItem label="API">

```bash
# Has anything arrived? last_seen_at is null until the first page view lands
curl https://api.siteqwality.com/rum/$APP_ID/ingest-status \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY"

curl https://api.siteqwality.com/rum/$APP_ID/sessions \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY"
```

</TabItem>
</Tabs>

If nothing shows up after a minute, check that:

- The snippet sits in the page's `<head>`.
- Your [Content Security Policy](/observability/rum/how-to/csp/) allows the hosts for the SDK version installed. SDK 2 needs the config CDN in `connect-src`; SDK 2.1 also needs `https://in-replay.siteqwality.com`.
- No ad blocker is blocking those hosts in your test browser.
- The client token belongs to this application.

## 5. Identify users and track custom events

After login, identify the user:

```javascript
SiteQwalityRUM.setUser({
  id: 'usr_abc123',
  email: 'alice@example.com',
  name: 'Alice',
});
```

The user then shows on the session in **RUM → Sessions**, and the session search finds it by any part of the ID or email, ignoring case.

For business events:

```javascript
// Track a user action
SiteQwalityRUM.addAction('checkout_completed', { variant: 'A' });

// Track a manual error (in addition to auto-captured ones)
try {
  await chargeCard();
} catch (err) {
  SiteQwalityRUM.addError(err, { feature: 'checkout', step: '3' });
  throw err;
}
```

## 6. Set up source maps (production)

Minified JS errors aren't very useful. Upload source maps so stacks resolve to original source. See the [Source maps how-to](/observability/rum/how-to/source-maps/).

<Aside type="tip">
Set `version` in `init()` and change it on every deploy. Errors carry it, and it must match the release you upload source maps to, byte for byte.
</Aside>
