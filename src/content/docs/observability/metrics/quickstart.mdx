<Aside type="note" title="Early access">
Logs, traces and metrics are in early access. To enable them for your account, email [hello@siteqwality.com](mailto:hello@siteqwality.com). Until then, telemetry sent from the account is refused.
</Aside>

1. Open [Add data](https://app.siteqwality.com/add-data?signal=metrics), select your platform and create a scoped ingest key. Choose a stable service name and environment. Keep the key on your server.
2. Follow the [curl guide](/observability/platforms/curl/) for a standalone OTLP JSON sample, or your language/platform guide for real instrumentation. Use `https://otlp.siteqwality.com/v1/metrics` for the OTLP signal endpoint and the required Authorization header. An arbitrary JSON record belongs to its adapter route, not an OTLP envelope.
3. Inspect the response, including partial-success counters. Accepted records reached storage or durable spill; this is separate from readable data.
4. Choose **Check again** in Add data, then open [Metrics](https://app.siteqwality.com/metrics). Set the recent time window and your service/environment. Check read permissions if the first-data query is denied.
5. Inspect a record/sample and its fields. Generate real application traffic before expecting a useful chart or trace tree. Save a useful view with a relative time range if you want it to move with the clock.

Use separate read-only credentials for API queries. See the [metrics reference](/observability/metrics/reference/), [query examples](/observability/query/) and [failure handling](/observability/ingest/#failure-handling). No browser test sends or stores your server ingest key.
