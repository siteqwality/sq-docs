## Ingest endpoint

```
POST https://metrics.siteqwality.com/metrics
Authorization: Bearer <api-key>
Content-Type: application/json
```

Body:

```json
{
  "metrics": [
    {
      "type": "gauge | counter | histogram",
      "name": "<metric_name>",
      "timestamp": "2026-05-03T14:32:00Z",   // optional RFC 3339 string; defaults to ingest time
      "value": 42.0,                           // gauge / counter
      "buckets": [{ "le": "10", "count": 0 }], // histogram
      "sum": 4250.0,                            // histogram
      "count": 20,                              // histogram
      "unit": "ms",                             // optional
      "tags": { "key": "value" }
    }
  ]
}
```

- Max **1,000 metrics per request**. Keep batches to about 500 points: the whole batch travels as one internal message with a size limit of about 250 KB, so a batch of heavily tagged points can be rejected before it reaches 1,000.
- `timestamp` must be an RFC 3339 string. A numeric (epoch) timestamp makes the request fail with `400`.
- Returns `202 Accepted` on enqueue. Points are usually queryable within about 30 seconds.
- Returns `400` for malformed payloads, `401` when the `Authorization` header is missing, and `403` for an unknown, revoked or expired key.

## Naming rules

Metric names must match `^[a-zA-Z0-9._]+$`. Dots and underscores are allowed; everything else (dashes, slashes, spaces) is rejected. Convention is dot-separated:

```
http.requests.total
http.request.duration_ms
db.connections.active
job.duration_seconds
```

## Tags

Free-form `string → string`. Tags can be filtered on and grouped by; cardinality matters. The `host` and `env` tags are also stored as their own columns.

**Reasonable**: `service`, `env`, `region`, `endpoint`, `status_class`, `queue`, `team`.

**Risky**: `user_id`, `request_id`, `full_url`, `session_id`, `email`, and anything else unique per request.

The account is derived from the API key; you never send it.

## Query endpoints

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/metrics/names` | Search metric names (`prefix`, `limit`). |
| `GET` | `/metrics/tag-keys` | List tag keys for a metric (`metric_name`). |
| `GET` | `/metrics/tag-values` | List values for a (`metric_name`, `tag_key`). |
| `GET` | `/metrics/query` | Time-series chart data. |
| `GET` | `/metrics/summary` | Aggregated table (`avg/min/max/latest` per group). |
| `GET` | `/metrics/histogram` | Histogram buckets and percentiles. See [histograms](/observability/metrics/how-to/histograms/). |
| `GET` | `/metrics/sources` | Distinct `source` values. Every metric sent to the ingest endpoint has the source `app`. |

These endpoints are on `https://api.siteqwality.com` and need a full-access API key; an ingest key gets `403`.

### `/metrics/query` parameters

| Param | Type | Description |
|---|---|---|
| `metric_name` | string | Required. |
| `aggregation` | string | `avg` (default), `max`, `min`, `sum`, `p50`, `p75`, `p90`, `p95`, `p99`, `rate`. |
| `group_by` | string | One tag key to split series by. |
| `start_time` / `end_time` | RFC 3339 | Time window. Default last 1 hour. |
| `resolution` | string | `auto`, `1m`, `5m`, `1h`, `6h`. Bucket width. |
| `filters` | string | JSON-encoded `{tag_key: tag_value}` map for filtering. |

Response:

```json
{
  "data": {
    "metric_type": "gauge",
    "unit": "ms",
    "series": [
      {
        "group": { "endpoint": "/api/checkout" },
        "points": [
          { "timestamp": "2026-05-03T14:00:00Z", "value": 42.5 },
          ...
        ]
      }
    ]
  }
}
```

### What each aggregation computes

`/metrics/query` reads gauges and counters. Histograms are stored separately and read with `/metrics/histogram`; querying a histogram name here returns no series.

| Aggregation | Computes, per time bucket |
|---|---|
| `avg`, `min`, `max`, `sum` | Over every raw point in the bucket, across all series that match the filters (or within each group when `group_by` is set). |
| `p50` to `p99` | Percentiles of those raw point values. |
| `rate` | The change in the bucket average since the previous bucket, divided by the bucket width in seconds, floored at zero. Meaningful only for a single series whose value is a running total. For per-interval counts, use `sum`. |

## Limits

| Constraint | Value |
|---|---|
| Metrics per ingest request | 1,000 (keep batches to about 500 points) |
| Metric name characters | `^[a-zA-Z0-9._]+$` |
| Retention (free tier) | 3 days |
| Retention (paid telemetry packs) | 15 days on the 50 GB pack; 30 days on the 200 GB and 1 TB packs |
| Maximum purchasable retention | 30 days |

Retention is resolved **per account**, not per metric or per source, and it is stamped onto each row when it is written. Metrics and histograms share one telemetry window with logs and traces.

Two consequences follow from stamping at write time. Upgrading extends the window on rows already stored as well as new ones. Downgrading is forward-only: rows keep the window they were written with, so cancelling a pack never deletes data early, and it does not shorten anything already stored.

<Aside type="caution" title="This page used to say 90 days">
Earlier versions of this page stated a 90-day default. That was never true on any plan after per-account retention shipped. The real maximum is 30 days, on the largest telemetry pack.
</Aside>
