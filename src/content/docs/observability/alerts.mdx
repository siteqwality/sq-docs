Telemetry alert rules and SLOs evaluate in the app, with instances, state history and SLO summaries, but they do not send notifications yet: a firing rule sends no email, webhook or on-call page and opens no incident or status-page update. Use uptime monitoring and its notifications for production paging.

## Threshold rules

Use the telemetry Alerts editor. Choose an event query or a metric query output, time window, evaluation interval and threshold direction. Configure critical, optional warning and recovery thresholds, required breach duration, keep-firing duration, no-data timeout and missing-data policy. Preview on a bounded window before enabling. Set a stable service, severity, runbook and group dimensions rather than a rule per dynamic request ID.

An event query can evaluate supported count, ratio and percentile analytics. A metric query refers to a named query or formula output. The preview validates the exact typed query and returns observed values and state. Maximum instances bound group expansion.

States distinguish healthy, pending, warning/firing, no data and evaluation error. Missing data is not zero: choose keep, no_data, alert or ok as the missing-data policy. Quota exhaustion can produce no_data with a quota reason, and partial or unfinished derived data can pause or qualify evaluation, so inspect the history reason before changing thresholds.

## SLOs

Choose a ratio SLI (good and total with compatible units) or a distribution SLI (query/output, latency threshold and unit), target and period. A distribution SLO needs actual distributions; a percentile scalar is not a count of good events. The standard paired burn windows include long and short windows; configure both so a short spike alone does not imply sustained burn.

Pause stops evaluation and mute changes notification eligibility. Edits are revision-aware: after a conflict, refresh instead of overwriting the other change. A shared rule cannot expose broader samples than its creator could read.

| Endpoint family | Operations |
|---|---|
| `/alert-rules/v2` | GET list, POST create. |
| `/alert-rules/v2/{id}` | GET detail, PUT update, DELETE remove. |
| `/alert-rules/preview` | POST typed preview. |
| `/alert-rules/v2/{id}/instances`, `/history` | GET instances and evaluations. |
| `/alert-rules/v2/{id}/pause`, `/resume`, `/mute` | POST actions; DELETE mute to unmute. |
| `/slos`, `/slos/{id}` | List/create/detail/update/remove. |
| `/slos/{id}/history`, `/summary` | GET SLO history and summary. |
| `/slos/{id}/pause`, `/resume`, `/mute` | Evaluation and mute actions. |

Use the editor or the generated API schemas for complete rule bodies and expected revisions. Notification groups and incident settings on a rule are saved but not used for delivery yet.
