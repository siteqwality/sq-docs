By the end of this guide you'll have replay activated for any session that throws an error, and you'll have watched a recorded session play back in the dashboard.

## Prerequisites

- A RUM application set up. See the [RUM quickstart](/observability/rum/quickstart/).
- The SDK installed in your app.

## 1. Check the application's privacy settings

New applications start on the **Balanced** [privacy level](/observability/rum/how-to/remote-config/#privacy-levels), which masks inputs and scrubs emails, card numbers and long digit runs from page text. **Strict** also masks all text and blocks images and video.

<Tabs syncKey="interface">
<TabItem label="Dashboard">

<Steps>

1. **RUM → Applications → your app → Settings → Privacy.**

2. Check that **Mask all user inputs** is on. (Almost always a yes, since your customers shouldn't see other customers' typed data.)

3. Turn on **Mask all text content** if your app displays sensitive content (financial info, PII).

4. Save.

</Steps>

</TabItem>
<TabItem label="API">

Set the level through the API. Send only the keys you change; the rest keep their stored values. Changing privacy needs an account admin or an API key with no scope restriction:

```bash
curl -X PATCH https://api.siteqwality.com/rum/$APP_ID \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"settings": {"privacy": {"level": "strict"}}}'
```

</TabItem>
</Tabs>

## 2. Add a recording rule to enable replay

Replay activates when a session matches a Replay [recording rule](/observability/rum/how-to/session-filters/). A new application already has one, **Errored sessions**, which replays every session with an error, so you can skip this step. If you deleted it, add one in **RUM → Recording rules**, or through the API:

```bash
curl -X POST "https://api.siteqwality.com/rum/$APP_ID/rules" \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Errored sessions",
    "capture": "replay",
    "conditions": [{ "kind": "error" }]
  }'
```

The SDK fetches rules on every page load, and an open tab refetches them when it becomes visible with a copy older than 5 minutes. A new rule reaches new page loads within 6 minutes; see [how long changes take](/observability/rum/how-to/remote-config/#how-long-changes-take-to-land).

## 3. Trigger an error in your app

Open your app, do something that throws an error in production code. (Or temporarily add `throw new Error('replay test')` to a button handler and click it.)

The SDK evaluates the rule as soon as it sends the error. Because an error rule could match any session, the recorder has been buffering since the page loaded, so the replay includes up to the last 60 to 120 seconds before the error. Keep using the page for a few seconds; segments upload within about 20 seconds, or when you leave the page.

## 4. Watch the replay

<Tabs syncKey="interface">
<TabItem label="Dashboard">

<Steps>

1. In **RUM → Sessions**, find your session (it has the error indicator).

2. Click its **Replay** badge to open the player. From the error's page under **RUM → Errors**, **Watch replay** opens the same replay at the error.

3. The video player loads. Hit play; scrub the timeline; jump to the error using its marker, or **Next error** (`]`).

</Steps>

</TabItem>
<TabItem label="API">

```bash
# The replay manifest: every window, page load and chunk, without URLs
curl https://api.siteqwality.com/rum/$APP_ID/sessions/$SESSION_ID/replay \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY"
```

Then request short-lived URLs for the chunks you want to play with `POST /rum/{app_id}/sessions/{session_id}/replay/chunks`. The key needs the `read:rum_replay` and `read:rum` scopes. See [retrieval](/observability/replay/reference/#retrieval).

</TabItem>
</Tabs>

## Privacy checklist

Before rolling out replay broadly:

- [ ] The application has a privacy level. An application on Custom with `mask_inputs: false` records input values.
- [ ] Sensitive text (PII, financial figures, health info) is covered by `mask_selectors`, or the application is on Strict.
- [ ] Payment forms match a `block_selectors` entry (not recorded at all), and pages that should never be recorded are in `never_record_urls`.
- [ ] Your privacy policy mentions session replay if you collect from EU/CA customers (GDPR/CCPA).
- [ ] Replay-enabled recording rules are scoped. Don't replay every session, just the interesting ones.
