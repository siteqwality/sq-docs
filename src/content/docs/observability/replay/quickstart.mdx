By the end of this guide you'll have replay activated for any session that throws an error, and you'll have watched a recorded session play back in the dashboard.

## Prerequisites

- A RUM application set up. See the [RUM quickstart](/observability/rum/quickstart/).
- The SDK installed in your app.

## 1. Set privacy defaults on the application

<Tabs syncKey="interface">
<TabItem label="Dashboard">

<Steps>

1. **RUM → Applications → your app → Settings → Privacy.**

2. Enable **Mask inputs**. (Almost always a yes, since your customers shouldn't see other customers' typed passwords.)

3. Enable **Mask text** if your app displays sensitive content (financial info, PII).

4. Save.

</Steps>

</TabItem>
<TabItem label="API">

Send only the keys you change; the rest keep their stored values. Changing privacy needs an account admin or an API key with no scope restriction:

```bash
curl -X PATCH https://api.siteqwality.com/rum/$APP_ID \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"settings": {"privacy": {"mask_inputs": true, "mask_text": false}}}'
```

</TabItem>
</Tabs>

## 2. Add a recording rule to enable replay

Replay activates when a session matches a Replay [recording rule](/observability/rum/how-to/session-filters/). A new application already has one, **Errored sessions**, which replays every session with an error, so you can skip this step. An application created before recording rules v2 may have none; add one in **RUM → Recording rules**, or through the API:

```bash
curl -X POST "https://api.siteqwality.com/rum/$APP_ID/rules" \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Errored sessions",
    "capture": "replay",
    "conditions": [{ "kind": "error" }]
  }'
```

The SDK fetches rules on every page load and refreshes them every 5 minutes. Allow up to about ten minutes for a new rule to reach every page; see [how long changes take](/observability/rum/how-to/remote-config/#how-long-changes-take-to-land).

## 3. Trigger an error in your app

Open your app, do something that throws an error in production code. (Or temporarily add `throw new Error('replay test')` to a button handler and click it.)

The SDK evaluates the rule as soon as it sends the error and starts the recorder. The replay starts at the error: it does not include what happened before it. Keep using the page for a few seconds; the first segment uploads within 30 seconds, or when you leave the page.

## 4. Watch the replay

<Tabs syncKey="interface">
<TabItem label="Dashboard">

<Steps>

1. In **RUM → Sessions**, find your session (it has the error indicator).

2. Click its **Replay** badge to open the player. From the error's page under **RUM → Errors**, **Watch replay** opens the same replay at the error.

3. The video player loads. Hit play; scrub the timeline; jump to the error using its marker, or **Next error** (`]`).

</Steps>

</TabItem>
<TabItem label="API">

```bash
# Get the segment URLs
curl https://api.siteqwality.com/rum/$APP_ID/replay/$SESSION_ID \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY"
```

You get a list of segments with presigned S3 URLs. The dashboard's player consumes these directly.

</TabItem>
</Tabs>

## Privacy checklist

Before rolling out replay broadly:

- [ ] Inputs are masked (`mask_inputs: true`) unless you have a strong reason to capture them.
- [ ] Sensitive text (PII, financial figures, health info) is wrapped in `<div class="rr-mask">` or behind a `mask_text: true` global setting.
- [ ] Pages with payment forms have `<div class="rr-block">` on the form (don't record at all).
- [ ] Your privacy policy mentions session replay if you collect from EU/CA customers (GDPR/CCPA).
- [ ] Replay-enabled recording rules are scoped. Don't replay every session, just the interesting ones.
