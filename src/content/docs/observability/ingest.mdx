## Endpoints and authentication

All paths below use `https://otlp.siteqwality.com`. The older hostnames `logs.siteqwality.com`, `metrics.siteqwality.com` and `traces.siteqwality.com` accept the same paths and authentication.

| POST path | Format | Credential |
|---|---|---|
| `/v1/logs`, `/v1/traces`, `/v1/metrics` | OTLP HTTP JSON or binary protobuf | `Authorization: Bearer YOUR_INGEST_KEY` |
| `/ingest` | JSON object/array, NDJSON or text lines | Authorization header |
| `/metrics` | Custom metric JSON, including v2 resource/points | Authorization header |
| `/api/v1/write` | Prometheus remote-write 1.x or 2.0, Snappy protobuf | Authorization header |
| `/v1/heroku` | `application/logplex-1`, octet-counted frames | Basic auth, key as password |
| `/v1/vercel` | Vercel log JSON/NDJSON | Authorization plus `x-vercel-signature` |
| `/v1/cloudflare` | Supported Logpush dataset JSON/NDJSON, optional gzip | Authorization header |
| `/v1/firehose` | Firehose protocol 1.0 envelope | `X-Amz-Firehose-Access-Key`, raw key |

Authorization routes accept Bearer, a bare key or Basic with the key as password. Keys are exactly 96 hexadecimal characters. Use an **ingest key** for this account: its `ingest_signals` list selects `logs`, `traces` and/or `metrics` (an empty list allows all three), and its API `scopes` list must be empty. A scoped full API key ingests only with the exact `write:logs`, `write:traces` and `write:metrics` scopes. Read-only keys cannot ingest, and ingest keys cannot call query APIs: query with a read-only key that has the needed `read:logs`, `read:traces` or `read:metrics` scopes, or with your signed-in session. A full API key with an empty scopes list has full access, so do not distribute it to exporters.

Only platforms that cannot set an Authorization header should use the matching `/k/...` route with one `api_key` query parameter, for example `/k/v1/logs?api_key=YOUR_INGEST_KEY`. That URL carries the credential and can leak through access logs, shell history, dashboards and screenshots: protect and rotate it, and never use it in a browser or public documentation. Credentials in two locations (Authorization plus `api_key`, duplicate keys or conflicting headers) are refused. Firehose has no `/k` route.

OTLP over gRPC (ports 443 and 4317) and syslog over TLS (port 6514) are not available yet; use OTLP/HTTP. There is no public UDP StatsD or UDP syslog port. Send StatsD to your own Collector, which exports OTLP/HTTP.

## Content types and compression

- OTLP protobuf: `Content-Type: application/x-protobuf`. OTLP JSON: `application/json`. Do not send an arbitrary JSON log to `/v1/logs`; use its OTLP `resourceLogs` envelope or `/ingest`.
- JSON logs: `application/json`, `application/x-ndjson` or `application/ndjson`. Raw lines: `text/plain`. The adapter recognizes common Docker/Kubernetes wrappers and retains custom structured fields.
- Custom metrics: `application/json`. Remote-write: Snappy-compressed protobuf with the matching remote-write content type/version; never Prometheus text exposition.
- HTTP supports identity, gzip and supported deflate encoding. Set `Content-Encoding` to the actual encoding, and do not compress twice.

| Bound | Value |
|---|---|
| Request bytes on the wire | 4,000,000 bytes |
| Inflated logs/traces body | 40,000,000 bytes |
| Inflated metrics body | 16,000,000 bytes |
| Maximum inflation ratio | 100:1 |
| Log body | 256 KiB, excess truncated and flagged |
| Attributes per record | 256 |
| Attribute key / typical string value | 256 characters / 16 KiB |
| Exception stack and database statement text | 32 KiB |
| Span name / events / links | 1,024 characters / 128 / 128 |

SDK batch record counts do not bound byte size, so split large payloads and monitor truncation and rejection counts. An invalid request can fail as a whole; a valid envelope can partially reject individual records.

## Timestamps and identity

Use current timestamps. Logs accept up to the smaller of seven days or retention minus one hour in the past, and two hours in the future; out-of-window times are clamped and the original retained as metadata. Spans in the same trace/request shift together. Metric points older than 24 hours or more than ten minutes in the future are rejected.

Prefer OTel resource fields `service.name`, `deployment.environment.name`, `service.version` and `host.name`. JSON aliases and `X-Service`/`X-Env` headers supply fallbacks, and a key's defaults apply when the record has no identity. Set stable identity before relying on services or correlation.

## What a success means

OTLP/HTTP returns **200** with an ExportResponse: inspect `partialSuccess` and the rejected record, point and span counters even when HTTP succeeded. JSON `/ingest` and `/metrics` return **200** with `accepted`, `rejected` and bounded `errors`. Platform log adapters return **200** using their platform contract. Firehose echoes the request ID and timestamp after delivery and fails a batch with rejected records. Remote-write returns **204** for full acceptance (2.0 also returns written-sample, histogram and exemplar headers) and a failure response for rejected records.

Accepted records are durably written before acknowledgment, though some can become queryable later. A success is not exactly-once delivery across new requests, a promise that every record was retained (exclusion and sampling rules still apply) or a latency SLA. Retrying an ambiguous failure can duplicate records; retain sender identity where supported.

## Failure handling

| Status | Action |
|---|---|
| 400 | Correct malformed envelopes, values, IDs or protocol headers. Inspect bounded errors. |
| 401 / 403 | Check the key, the selected signal, revocation and access. Do not retry indefinitely. |
| 413 | Split the request by bytes. An unchanged retry will fail again. |
| 415 | Correct Content-Type, Content-Encoding or protocol. |
| 429 | Honor `Retry-After`; inspect rate, series or per-signal [quota](/observability/billing/#limits-and-notifications). Use backoff with jitter and a local queue. |
| 5xx | Retain buffered data and retry with bounded backoff. Contact support with time, signal and request ID, never the key. |

Confirm first retained data with `GET https://api.siteqwality.com/telemetry/first-data/logs` (or `traces`, `metrics`) using read credentials, or open the Logs, Traces or Metrics page. Results are permission-scoped, so a read denial is not an ingest refusal.
