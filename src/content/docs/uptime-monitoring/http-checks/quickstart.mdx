By the end of this guide you'll have an HTTP check running, with a notification that fires when it fails. The examples monitor `https://mock.codes/200`, which always returns `200 OK`; use your own URL if you prefer.

## Create the check

<Tabs syncKey="interface">
<TabItem label="Dashboard">

<Steps>

1. **Go to Observe → Monitors, open Add Monitor and choose HTTP Monitor.**

2. **Fill in the basics.**
   - **Name:** `Mock 200 endpoint`
   - **URL or IP:** `https://mock.codes/200`
   - **Check Interval:** `5m`
   - **Method:** `GET` (under **Request**)

3. **Pick a notification group** under **Alerting** (or create one). Email is the fastest channel to test.

4. **Click Submit.**

</Steps>

The check runs immediately, and the first result lands within seconds.

</TabItem>
<TabItem label="API">

<Steps>

1. **Create an API key** under **Settings → API keys** and export it:

   ```bash
   export SITEQWALITY_API_KEY="<your API key>"
   ```

2. **POST to `/http/job`.**

   ```bash
   curl -X POST https://api.siteqwality.com/http/job \
     -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
     -H "Content-Type: application/json" \
     -d '{
       "friendly_name": "Mock 200 endpoint",
       "method": "GET",
       "uri": "https://mock.codes/200",
       "timeout_ms": 15000,
       "run_interval_seconds": 300,
       "monitor_tls": false,
       "monitor_dns": false
     }'
   ```

3. **Save the `id` from the response.** You'll use it to fetch results, update settings, or delete the check later.

4. **(Optional) Choose notification groups.**

   With `group_notification_ids` omitted, the monitor is attached to your account's [default group](/incident-management/notifications/default-routing/#the-default-notification-group). To use other groups, pass their UUIDs at create time or later with `PUT /http/job/{job_id}`. An explicit `[]` creates a monitor that notifies no one.

</Steps>

The full request schema is in the [API Reference](/api-reference/operations/create_http_job/).

</TabItem>
</Tabs>

## Verify it's working

<Steps>

1. **Wait for the first result.** The monitor's status changes from "pending" to "success."

2. **Look at the recent results.**
   - Dashboard: open the monitor, scroll to **Recent Checks**.
   - API: `GET /http/job/{job_id}/recent`.

3. **Force a failure to test notifications.** Edit the check and change the URL to `https://mock.codes/500`. The next tick will fail, the monitor's status will flip, and your notification group will fire.

4. **Flip it back.** Restore the URL to `https://mock.codes/200`. The all clear goes out after the recovery period (2 healthy checks on a new monitor).

</Steps>
