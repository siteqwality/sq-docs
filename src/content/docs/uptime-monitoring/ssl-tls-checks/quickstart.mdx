This turns on TLS monitoring for an existing [HTTP check](/uptime-monitoring/http-checks/quickstart/) with an `https://` URL.

## 1. Enable TLS monitoring

<Tabs syncKey="interface">
<TabItem label="Dashboard">

<Steps>

1. Open the HTTP check and choose **Edit monitor**.

2. Under **Optional checks**, turn **Monitor TLS/SSL** on and click **Save**. New HTTP monitors have it on already.

</Steps>

</TabItem>
<TabItem label="API">

With an [API key](/getting-started/account-and-team/#generate-api-keys) exported as `SITEQWALITY_API_KEY`, and `$JOB_ID` set to the HTTP check's `id`:

```bash
curl -X PUT https://api.siteqwality.com/http/job/$JOB_ID \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "monitor_tls": true }'
```

New HTTP checks have it on unless created with `"monitor_tls": false`.

</TabItem>
</Tabs>

The TLS check runs once a day, within a flexible window of up to four hours, so the first result may take a few hours to appear.

## 2. View the TLS check status

<Tabs syncKey="interface">
<TabItem label="Dashboard">

The HTTP check page shows an **SSL** tile with the certificate status and days until expiry. Click it to open the **TLS Checks** tab.

</TabItem>
<TabItem label="API">

The HTTP check's response includes the paired `tls_job_id`. Set `$TLS_JOB_ID` to it and fetch the TLS check:

```bash
curl https://api.siteqwality.com/tls/job/$TLS_JOB_ID \
  -H "Authorization: Bearer $SITEQWALITY_API_KEY"
```

You get back the `TlsJob`:

```json
{
  "id": "...",
  "http_job_id": "...",
  "current_status": "good",
  "domain": "api.example.com",
  "expiry_date": "2026-12-15T08:00:00Z",
  "last_run_at": "2026-05-03T14:32:00Z",
  ...
}
```

</TabItem>
</Tabs>
