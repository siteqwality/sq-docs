The full request/response schema is in the auto-generated [API Reference](/api-reference/). This page is the human-readable cheat sheet.

## Object: `TlsJob`

| Field | Type | Description |
|---|---|---|
| `id` | uuid | TLS check ID. |
| `account_id` | uuid | Owning account. |
| `http_job_id` | uuid | The HTTP check this TLS check was paired with on creation. |
| `current_status` | enum | See status table below. |
| `domain` | string | Hostname extracted from the HTTP check's URL. |
| `port` | int | Port the handshake connects to. `443` unless set with `tls_port` on the HTTP check. |
| `expiry_date` | rfc3339 \| null | Cert's `notAfter` (set after first successful handshake). |
| `last_run_at` | rfc3339 \| null | Most recent handshake timestamp. |
| `last_status_change_at` | rfc3339 \| null | When `current_status` last transitioned. |
| `created_at` | rfc3339 | When the TLS check was first provisioned. |

## Status enum

| Status | Meaning |
|---|---|
| `good` | Most recent handshake succeeded and the certificate has not expired. The chain and hostname match are recorded but do not change the status. |
| `bad` | The certificate has expired. |
| `unknown` | The check has not run yet, or could not connect or read a certificate (DNS failure, refused or timed-out connection, nothing serving TLS on the port). |

A TLS check that stays `unknown` for more than 24 hours means certificate expiry is not being watched. Site Qwality emails the account owners once per stretch and records a `tls_unknown` [monitor event](/uptime-monitoring/http-checks/reference/#monitor-events) on the HTTP check. A wrong port is a common cause: set `tls_port`.

## Endpoints

The TLS check is read-only via its own endpoints (you create it implicitly by setting `monitor_tls: true` on an HTTP check):

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/tls/job/{tls_job_id}` | Fetch current status. |
| `GET` | `/tls/job/{tls_job_id}/recent` | Recent handshake results. |

To enable/disable TLS monitoring, `PUT /http/job/{job_id}` with `monitor_tls: true|false`.

## Port

The handshake connects to port `443` by default. To check a certificate served elsewhere, send `tls_port` (1 to 65535) on `POST /http/job` or `PUT /http/job/{job_id}`. `GET /http/job/{job_id}` returns the port in use as `tls_port` when TLS monitoring is on.

| Request | Result |
|---|---|
| `tls_port` outside 1 to 65535 | `400`. |
| `tls_port` with `monitor_tls: false` | `400`. |
| `PUT` with `tls_port` on a check without TLS monitoring and no `monitor_tls` | `409`. Send `monitor_tls: true` with it. |
